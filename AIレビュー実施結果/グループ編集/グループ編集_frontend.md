# グループ編集 レビュー結果

## 指摘事項

### 1. 管理者変更チェックの適用条件が設計と逆転している
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/groups/GroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/040.グループ管理/グループ編集.md の「更新ボタン押下」では、編集モードかつログインユーザーがテナント管理者でない場合に管理者変更チェックを実施する仕様。
  - 実装: frontend/src/pages/groups/GroupEdit.jsx:204-224 で `if (isTenantAdmin) { ... isManagerChanged(...) ... }` となっており、テナント管理者の場合にのみ管理者変更チェックしている。
- 指摘内容:
  - 管理者変更チェックの実行対象が逆になっており、設計上チェック対象のユーザーで検証されない。権限制御と業務ルールの逸脱であり、更新可否判定が誤る。
- 期待されるテスト:
  - 非テナント管理者が管理者変更ありで更新した場合に GRP02002 が表示されること。
  - 非テナント管理者が管理者変更なしで更新できること。
  - テナント管理者では同条件で不要な GRP02002 が出ないこと。

### 2. 例外処理不備により未捕捉例外で処理継続不能となる
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/groups/GroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/040.グループ管理/グループ編集.md の「画面初期表示（編集モード）」「更新ボタン押下」では、取得失敗時やチェックエラー時にメッセージ表示して処理を終了する仕様。
  - 実装: frontend/src/pages/groups/GroupEdit.jsx:117 で `catch (e)` 内にもかかわらず `console.error(..., error)` と未定義変数を参照。さらに frontend/src/pages/groups/GroupEdit.jsx:188-248 の更新 confirm 内は `fetch` 失敗時例外を囲う try/catch がなく `throw` が未捕捉になる。
- 指摘内容:
  - 初期表示失敗時・更新前チェック API 失敗時に想定メッセージ制御へ遷移せず、未捕捉例外で UI が不安定化する可能性がある。
- 期待されるテスト:
  - getGroup 失敗時にクラッシュせずエラーメッセージが表示されること。
  - getAuthMe/listGroupMembers が 4xx/5xx の場合に未捕捉例外にならず、エラーメッセージとローディング解除が行われること。

### 3. 編集初期表示で対象グループ不存在時の遷移要件が未実装
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/groups/GroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/040.グループ管理/グループ編集.md の「画面初期表示（編集モード）」で、対象グループが存在しない場合は COM01009 を表示してグループ検索画面へ遷移する仕様。
  - 実装: frontend/src/pages/groups/GroupEdit.jsx:60-75, 107-109 では COM01009 表示のみで、`navigate('/groups')` が実行されない。
- 指摘内容:
  - 不正な groupId で画面に留まり続けるため、画面遷移仕様に不一致。
- 期待されるテスト:
  - groupId 不存在時に COM01009 表示後、グループ検索画面へ遷移すること。

### 4. キャンセル時の変更有無判定がなく常時確認ダイアログ表示となっている
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/groups/GroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/040.グループ管理/グループ編集.md の「キャンセルボタン押下」では、入力内容が変更されている場合のみ COM01008 を表示する仕様。
  - 実装: frontend/src/pages/groups/GroupEdit.jsx:309-313 で変更有無を判定せず常に COM01008 を表示。
- 指摘内容:
  - 非変更時の UX と仕様に不一致。不要な確認が常時発生する。
- 期待されるテスト:
  - 未変更状態でキャンセル押下時に確認なしで遷移すること。
  - 変更ありでキャンセル押下時に COM01008 が表示されること。

### 5. 所属ユーザー削除の確認メッセージが要件未達
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/groups/GroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/040.グループ管理/グループ編集.md の「所属ユーザー削除ボタン押下」では、COM01007 と削除対象（ログインID、ユーザー名）を表示する仕様。
  - 実装: frontend/src/pages/groups/GroupEdit.jsx:318 で固定文言 `対象のデータを削除します。よろしいですか？` のみ。
- 指摘内容:
  - メッセージID要件および対象情報表示要件を満たしていないため、誤操作防止の観点で不十分。
- 期待されるテスト:
  - 削除確認ダイアログに COM01007 相当文言と対象ユーザー情報が表示されること。
  - キャンセル時に対象行が削除されないこと。

### 6. ユーザー検索・追加の表示仕様に一部不一致がある
- 優先度: Low
- 種別: 実装不備
- 対象: frontend/src/pages/groups/GroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/040.グループ管理/グループ編集.md の「ユーザー検索ダイアログ・検索ボタン押下」「追加ボタン押下」では、0件時 COM01003 表示、追加後はメールアドレス昇順表示。
  - 実装: frontend/src/pages/groups/GroupEdit.jsx:550 は固定文言表示のみ（COM01003 明示なし）。frontend/src/pages/groups/GroupEdit.jsx:358-362 の追加処理でソートが行われない。
- 指摘内容:
  - 画面文言統一と一覧表示順に設計との差分がある。
- 期待されるテスト:
  - 検索0件時のメッセージ表示が設計/メッセージ定義どおりであること。
  - ユーザー追加後に所属一覧がメールアドレス昇順で表示されること。

### 7. 単体テスト観点に対してフロントエンドテストが未整備
- 優先度: Middle
- 種別: テスト不足
- 対象: グループ編集機能（frontend/src/pages/groups/GroupEdit.jsx）
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md の「単体テスト観点」（正常系、入力値バリエーション、境界値、分岐条件、データ入出力、非更新確認、異常系）。
  - 実装: frontend 配下に GroupEdit の単体テストコードが存在しない（前提条件とも一致）。
- 指摘内容:
  - 主要分岐・異常系・境界値の保証がないため、仕様逸脱や回 regressions を検知できない。
- 期待されるテスト:
  - 正常系: 新規登録成功、編集更新成功、ダイアログ検索成功、追加済表示切替。
  - 入力値バリエーション/境界値: グループ名必須、100文字境界、101文字超過、空白入力。
  - 分岐条件: 編集/新規モード、管理者変更あり/なし、テナント管理者/非管理者、キャンセル分岐。
  - データ入出力: API成功時の formData 反映、メンバー追加/削除/管理者設定、ページング。
  - 非更新確認: 確認ダイアログでキャンセルした場合に API 未実行。
  - 異常系: 各 API 失敗時のメッセージ表示、ローディング解除、遷移制御。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足: 新規登録成功、編集更新成功、編集初期表示成功、ユーザー検索成功、ユーザー追加済表示切替の検証が未整備。
- 入力値バリエーション不足: グループ名の未入力、空白のみ、通常文字列、マルチバイト文字列の検証が未整備。
- 境界値不足: グループ名 100 文字許容、101 文字拒否、検索条件長、ページング境界（1ページ目/最終ページ）の検証が未整備。
- 分岐条件不足: 新規/編集、管理者変更有無、テナント管理者/非管理者、確認ダイアログ OK/Cancel、管理者行削除不可の分岐検証が未整備。
- データ入出力不足: getGroup 取得結果の反映、メンバー一覧更新、setManager 反映、removeMember 反映、検索結果 totalCount/page の反映検証が未整備。
- 非更新確認不足: COM01006/COM01008 で Cancel 時に API を呼ばないこと、状態が保持されることの検証が未整備。
- 異常系不足: getGroup/getAuthMe/listGroupMembers/create/update/searchUsers の通信失敗・非200応答・不正レスポンス時挙動の検証が未整備。

## 総評
- High 指摘は、権限制御分岐の逆転と例外処理不備であり、業務ルール逸脱と実行時障害に直結するため最優先で修正が必要。
- Middle 指摘は、遷移仕様・確認ダイアログ条件・削除メッセージ仕様の不一致で、ユーザー操作性と要件適合性に影響する。
- フロントエンド単体テスト未整備により、分岐/異常系の品質保証が不足しているため、High 修正後に観点ベースでテスト整備を並行実施すべき。
