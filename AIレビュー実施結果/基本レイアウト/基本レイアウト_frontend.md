# 基本レイアウト レビュー結果

## 指摘事項

### 1. 権限に応じたメニュー表示制御が実装されていない
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/components/Layout.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md の「初期表示」「項目定義」で、ログインユーザーの権限を取得し、使用可能な機能のみ表示すること、機能が一つも表示されない分類は表示しないことを定義している。あわせて spec/基本設計/概要資料/外部設計/ユーザーの権限について.md で機能ごとの利用権限が定義されている。
  - 実装: frontend/src/components/Layout.jsx では menuConfig を固定値で定義し、そのまま全分類・全機能を描画している。frontend/src/common/UserAuthority.jsx に権限取得処理は存在するが Layout から呼び出されておらず、frontend/src/auth/AuthContext.jsx でもレイアウト表示判定に必要な権限情報を保持・提供していない。
- 指摘内容:
  - 初期表示時にログインユーザーの権限取得とメニューのフィルタリングが行われていないため、設計上は非表示であるべき機能が全ユーザーに表示される。これにより、空分類を非表示にする仕様も同時に満たせていない。権限制御は基本レイアウトの中心仕様であり、現状は設計逸脱かつ認可観点の重大な欠落である。
- 期待されるテスト:
  - TENANT_ADMIN、MASTER_DATA_ADMIN、一般ユーザーなど権限別に、表示される機能分類・機能名が設計どおりであること。
  - 権限を持たない機能が DOM 上に描画されないこと。
  - 権限フィルタリング後に配下機能が 0 件になった分類が表示されないこと。

### 2. プリセットクエリー配下メニューの遷移先が未定義で、クリックしても画面が表示されない
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/components/Layout.jsx、frontend/src/App.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md の「機能名クリック」で、クリックした機能の画面に遷移することを定義している。spec/レイアウトサンプル/基本レイアウト/index.html でもプリセットクエリー配下の画面遷移を前提にメニューが構成されている。
  - 実装: frontend/src/components/Layout.jsx では /preset-queries と /preset-query-permissions をメニューに定義している一方、frontend/src/App.jsx には対応する Route 定義が存在しない。そのため Link クリック後に一致する Route がなく、メインコンテンツが空白になる。
- 指摘内容:
  - メニュー項目が表示されているにもかかわらず遷移先画面が未登録であるため、ユーザーは選択状態のメニューだけ見えて内容のない画面に遷移する。画面遷移機能として成立しておらず、レイアウトから利用可能機能へ到達できるという設計を満たしていない。
- 期待されるテスト:
  - サイドメニューに表示される全 path について、クリック時に対応画面が描画されること。
  - Route 未定義のメニュー項目がレイアウトに残っていないこと。
  - active 表示と実際の描画コンテンツが一致すること。

### 3. 全画面切替のアイコン表示が状態に応じて切り替わらない
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/components/Layout.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md のヘッダー項目定義で、全画面表示時は角が内向きのアイコンへ切り替わることを定義している。spec/レイアウトサンプル/基本レイアウト/index.html でも fullscreenchange に応じてアイコンと title を更新している。
  - 実装: frontend/src/components/Layout.jsx では requestFullscreen と exitFullscreen の呼び分けのみ実装され、ボタン表示は常に同じ記号のままで、fullscreenchange を購読して表示状態を更新する処理が存在しない。
- 指摘内容:
  - 全画面切替自体は実装されているが、設計で求められている状態表示が欠落している。とくにブラウザ側操作や Esc による全画面解除時に UI 状態と実状態が乖離するため、利用者に誤認を与える。
- 期待されるテスト:
  - 通常表示と全画面表示でアイコンと title が切り替わること。
  - fullscreenchange 発火時にボタン表示が同期すること。
  - 全画面解除後に通常表示のアイコンへ戻ること。

### 4. 基本レイアウトの単体テストが未作成で、仕様上重要な分岐が未検証である
- 優先度: Middle
- 種別: テスト不足
- 対象: 基本レイアウト
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md では、単体テスト観点として正常系、入力値バリエーション、境界値、分岐条件、データ入出力、非更新確認、異常系を確認対象としている。
  - 実装: フロントエンドの Layout 関連テストコードは確認できず、権限制御、画面遷移、全画面切替、表示切替といった主要仕様に対する自動テストが存在しない。
- 指摘内容:
  - 本機能は認証状態、権限、ルーティング、表示状態の複数分岐を持つが、現状はそれらを担保するテストが 1 件もない。とくに High 指摘の権限制御と未定義 Route は、仕様ベースのテストがあれば早期に検出できた不備である。
- 期待されるテスト:
  - 正常系: 初期表示時にヘッダー、サイドメニュー、ユーザー名、既定の折り畳み状態が設計どおりであること。
  - 入力値バリエーション: 権限別の表示差分、ユーザー名の有無、長い名称の表示崩れ有無を確認すること。
  - 分岐条件: サイドバー展開/収納、カテゴリ展開/折り畳み、全画面 ON/OFF、Route 遷移の分岐を確認すること。
  - 異常系: 権限取得失敗時、全画面 API 非対応時、Route 未定義時の安全な挙動を確認すること。

### 5. 権限取得失敗時や全画面 API 失敗時のエラー表示仕様が設計・実装ともに明確でない
- 優先度: Middle
- 種別: 設計確認事項
- 対象: 基本レイアウト
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md には正常系イベントは定義されているが、権限取得失敗、認証情報欠落、Fullscreen API 失敗時の画面表示や通知方法は記載されていない。spec/050.テスト/テスト観点.md では異常系として外部連携失敗や権限不足時の振る舞い確認を求めている。
  - 実装: frontend/src/common/UserAuthority.jsx は権限取得失敗時に空配列を返す実装で、ユーザー通知方針が見えない。frontend/src/components/Layout.jsx の全画面切替処理にも失敗時の UI フィードバックが存在しない。
- 指摘内容:
  - 失敗時の期待挙動が設計上定義されていないため、実装者ごとに異なる判断になりやすく、異常系テストの期待値も定められない。ユーザーに何を表示すべきか、再試行可否、機能継続可否を先に明確化すべきである。
- 期待されるテスト:
  - 権限取得 API 失敗時に、ユーザーへ通知するのか、メニュー非表示にするのか、再試行させるのかが設計どおりであること。
  - Fullscreen API 失敗時に、画面が不整合な状態にならず適切なメッセージまたはフォールバックとなること。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足: 初期表示時のサイドメニュー展開状態、機能分類の初期折り畳み状態、ログインユーザー名表示、機能クリック時の遷移成功が未検証。
- 入力値バリエーション不足: 権限種別ごとの表示差分、ユーザー名未設定時、長いユーザー名表示時のレイアウトが未検証。
- 境界値不足: 権限を 1 件も持たない場合、分類内機能が 0 件になる場合、メニュー項目数が多い場合の表示が未検証。
- 分岐条件不足: サイドバー展開/収納、カテゴリ展開/折り畳み、全画面の ON/OFF、active 表示の切り替えが未検証。
- データ入出力不足: 認証コンテキストから取得したユーザー情報・権限情報が UI に正しく反映されること、各 menu path が有効な Route に接続していることが未検証。
- 非更新確認不足: 権限のない機能が表示されないこと、Route 未定義のメニューが表示されないこと、無関係な操作で表示状態が変化しないことが未検証。
- 異常系不足: 権限取得失敗時、認証情報欠落時、Fullscreen API 失敗時、未定義 Route 遷移時の挙動が未検証。

## 総評
- High 指摘は、権限制御未実装による設計逸脱と、プリセットクエリー配下の遷移不能という機能停止に直結する 2 点である。
- 現状の基本レイアウトは見た目の骨格はあるが、認可と画面遷移という中核仕様が未充足で、利用者影響が大きい。
- まずは権限取得とメニュー表示制御、ついで Route 定義の整合を修正し、その後に全画面表示の UI 同期と単体テスト整備を進めるべきである。

## 残留リスク・確認できなかった範囲
- 権限取得 API の正式仕様、AuthContext が保持すべき認証情報の確定仕様までは本レビュー対象外のため、連携契約の妥当性は未確認。
- 基本レイアウトに対応する CSS 実装は未提示のため、表示崩れやレスポンシブ要件の充足度は確認できていない。
- フロントエンドの自動テスト基盤自体が未整備に見えるため、今後のテスト追加時に採用するテストランナーとモック方針は別途確認が必要。
