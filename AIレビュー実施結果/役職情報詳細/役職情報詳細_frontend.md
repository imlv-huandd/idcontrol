# 役職情報詳細 レビュー結果

## 指摘事項

### 1. 編集対象の履歴選択が設計逸脱（選択中履歴ではなく先頭履歴を編集）
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/organizations/PositionDetail.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/070.組織情報/役職情報詳細.md（編集ボタン押下時は「現在表示している履歴」の登録内容を編集）
  - 実装: frontend/src/pages/organizations/PositionDetail.jsx（switchEditMode で Object.values(historyData)[0] を採用し、historySelect を参照していない）
- 指摘内容:
  - 履歴を選択していても編集開始時に常に先頭履歴へ切り替わるため、ユーザーが意図しない履歴を更新するリスクがある。
- 期待されるテスト:
  - 履歴Bを選択後に編集モードへ遷移し、フォーム値が履歴Bの内容を保持することを検証する。

### 2. 詳細表示モードの履歴初期選択（有効開始日最大）が未実装
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/organizations/PositionDetail.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/070.組織情報/役職情報詳細.md（詳細表示モード初期選択は有効開始日が最大のレコード）
  - 実装: frontend/src/pages/organizations/PositionDetail.jsx（historySelect 初期値は空文字のままで、履歴取得後に初期選択を設定していない）
- 指摘内容:
  - 初期表示時の履歴選択が空のままになり得るため、設計上の初期表示要件を満たしていない。
- 期待されるテスト:
  - 複数履歴取得時に、有効開始日最大レコードが初期表示されることを検証する。

### 3. 変更有無チェックのメッセージIDが設計不一致
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/organizations/PositionDetail.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/070.組織情報/役職情報詳細.md（変更有無チェックのメッセージIDは ORG05002）
  - 実装: frontend/src/pages/organizations/PositionDetail.jsx（inputChangesCheck で messages.ORG02002 を使用）
- 指摘内容:
  - 仕様上のメッセージIDと実装が一致しておらず、運用上のメッセージ統制・設計トレーサビリティを損なう。
- 期待されるテスト:
  - 変更なし更新時に表示されるメッセージID/文言が ORG05002 と一致することを検証する。

### 4. 履歴追加チェック（ORG05003）の条件式が設計条件と乖離
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/organizations/PositionDetail.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/070.組織情報/役職情報詳細.md（変更前開始日 < 新開始日 < 変更前終了日）
  - 実装: frontend/src/pages/organizations/PositionDetail.jsx（inputChangesCheck の OR 条件が優先順位依存で評価され、設計意図と一致しない判定になり得る）
- 指摘内容:
  - 境界外判定の条件構成が曖昧で、許容すべき日付を誤ってエラーにする、または逆に通すリスクがある。
- 期待されるテスト:
  - 新開始日が「旧開始日+1日」「旧終了日-1日」「旧開始日と同日」「旧終了日と同日」の各ケースで期待通り判定されることを検証する。

### 5. 基本情報エラーと追加情報エラーの表示競合（setErrors 上書き）
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/organizations/PositionDetail.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/070.組織情報/役職情報詳細.md（基本情報入力チェックと追加情報入力チェックをともに実施）
  - 実装: frontend/src/pages/organizations/PositionDetail.jsx（validate と validateAttribute がそれぞれ setErrors を行い、後段で前段結果を上書き）
- 指摘内容:
  - 複数カテゴリの入力不備が同時にある場合、ユーザーへ必要なエラーが十分表示されない可能性がある。
- 期待されるテスト:
  - 基本情報と追加情報で同時にエラーを発生させ、双方のエラーメッセージが同時表示されることを検証する。

### 6. 履歴表示フォーマットが設計記載（yyyy/mm/dd）と不一致
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/organizations/PositionDetail.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/070.組織情報/役職情報詳細.md（履歴表示形式は yyyy/mm/dd ～ yyyy/mm/dd）
  - 実装: frontend/src/pages/organizations/PositionDetail.jsx（startDate/endDate をそのまま連結し、フォーマット変換なし）
- 指摘内容:
  - API 返却が yyyy-mm-dd の場合、画面表示が設計形式と一致しない。
- 期待されるテスト:
  - 履歴表示文字列が yyyy/mm/dd 形式で描画されること、および終了日 9999-12-31 の場合に「～」省略表示となることを検証する。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足:
  - 詳細初期表示で有効開始日最大履歴が初期選択されること。
  - 編集モード遷移時に選択中履歴が編集対象になること。
  - 権限ありユーザーのみ編集ボタンが表示されること。
- 入力値バリエーション不足:
  - 追加情報の入力タイプ別（半角英字/数字/英数/全角/半角/整数/正整数/日付/日時/フラグ）の妥当値・不正値。
  - 必須属性と任意属性の空値パターン。
- 境界値不足:
  - テナント役職ID/役職名 100文字境界、序列 3桁境界。
  - 履歴追加チェックの日付境界（旧開始日+1日、旧終了日-1日、同日）。
- 分岐条件不足:
  - CREATE/VIEW/EDIT 各モードでの活性/非活性、表示/非表示分岐。
  - notChange 属性の新規時編集可・編集時編集不可分岐。
  - 変更なし更新時のエラー分岐。
- データ入出力不足:
  - getOrgPosition 成功時に履歴・フォームへ正しく反映されること。
  - create/update の送信 payload（型変換含む）が仕様通りであること。
- 非更新確認不足:
  - hasChanged=true 時の COM01008 表示とキャンセル時の遷移。
  - hasChanged=false 時に確認なしで戻ること。
- 異常系不足:
  - 取得API/登録API/更新API の HTTP エラー、業務エラーコード、通信例外時のメッセージ表示と復帰動作。

## 総評
- High 指摘として、履歴選択編集の設計逸脱、履歴初期選択未実装、メッセージID不整合、履歴追加チェック条件不備を確認した。
- これらは誤更新や誤判定を引き起こし得るため、リリース前に優先修正が必要。
- 併せてテスト未整備により回帰検知が不可能な状態であり、spec/050.テスト観点準拠のテスト作成を同時実施すべき。

## 残留リスク・確認できなかった範囲
- バックエンド側で履歴分割更新を担保しているか（PUT 更新API内部仕様）が本レビュー範囲外のため未確認。
- spec/050.テスト/テスト観点.md の詳細粒度（画面個別ケース）と単体テスト仕様書との完全トレースは、該当テスト資産作成時に再確認が必要。
