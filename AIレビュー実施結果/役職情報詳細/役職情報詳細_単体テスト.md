# 役職情報詳細 レビュー結果

## 指摘事項

### 1. 更新時の履歴追加分岐が未網羅
- 優先度: High
- 種別: 項目不足
- 対象: 単体テスト仕様書‗役職情報詳細.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) の「更新ボタン押下」で、有効開始日が変更された場合は変更前データの有効終了日更新と新規履歴登録に分岐し、[spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) の「バリデーション定義」で ORG05003（履歴追加チェック）が定義されている。
  - 実装: [単体テスト仕様書‗役職情報詳細.csv](単体テスト/単体テスト仕様書‗役職情報詳細.csv) の No.6、No.7、No.20、No.27 は、有効開始日変更なしの更新、楽観排他、変更なし更新のみで、履歴追加チェックと履歴分岐の検証がない。
- 指摘内容:
  - 更新時に有効開始日を変更した場合の分岐が項目表に存在せず、変更前レコードの有効終了日更新、新規履歴の登録、ORG05003 のエラー条件、更新条件不一致時の COM01010 を確認できない。
- 期待されるテスト:
  - 有効開始日を変更して更新した場合に、変更前データの有効終了日が新有効開始日の前日になること
  - 変更後データが新規履歴として登録されること
  - ORG05003 のエラー条件になるケース
  - 更新条件不一致時に COM01010 が表示されるケース

### 2. 詳細表示初期表示の0件時と複数履歴表示が未確認
- 優先度: Middle
- 種別: 項目不足
- 対象: 単体テスト仕様書‗役職情報詳細.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) の「初期表示（詳細表示モード）」で、役職が存在しない場合は COM01009 を表示してダイアログを閉じること、また履歴は有効開始日の降順で取得し初期選択は最大の有効開始日であることが定義されている。
  - 実装: [単体テスト仕様書‗役職情報詳細.csv](単体テスト/単体テスト仕様書‗役職情報詳細.csv) の No.2 は既存データの表示のみで、0件時のエラー、複数履歴時の並び順、初期選択を確認していない。
- 指摘内容:
  - 詳細表示の0件時に COM01009 を出してダイアログを閉じる経路が欠落している。
  - 複数履歴を取得した場合の降順ソートと初期選択が最大有効開始日になることを確認するケースがない。
- 期待されるテスト:
  - 役職情報が存在しない場合に COM01009 が表示され、ダイアログが閉じること
  - 複数履歴がある場合に有効開始日の降順で履歴セレクトが表示されること
  - 初期選択が最新履歴になること
  - 選択中履歴の内容が各項目に反映されること

### 3. 詳細表示モードの権限制御とボタン表示が設計と不一致
- 優先度: Middle
- 種別: 記載不足
- 対象: 単体テスト仕様書‗役職情報詳細.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) では、詳細表示モードで編集ボタンはマスターデータ管理者のみ表示し、それ以外は非表示とされている。
  - 実装: [単体テスト仕様書‗役職情報詳細.csv](単体テスト/単体テスト仕様書‗役職情報詳細.csv) の No.2 は「更新ボタンが表示されること」と記載しており、設計上の編集ボタン表示条件と一致していない。No.21、No.22 は更新/API の権限確認であり、詳細表示時のボタン表示確認ではない。
- 指摘内容:
  - 詳細表示モードのボタン表示が設計とずれており、編集ボタンの表示・非表示を確認するケースが不足している。
  - 管理者と非管理者で表示差分を確認できないため、権限制御の仕様確認として不十分である。
- 期待されるテスト:
  - マスターデータ管理者ログイン時に編集ボタンが表示されること
  - 非管理者ログイン時に編集ボタンが非表示であること
  - 詳細表示モードでは更新ボタンが表示されないこと

### 4. 編集モード遷移とキャンセル分岐が未網羅
- 優先度: Middle
- 種別: 項目不足
- 対象: 単体テスト仕様書‗役職情報詳細.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) の「編集ボタン押下」「キャンセルボタン押下」で、タイトル切替、履歴非表示、入力可否切替、変更不可項目の readonly 維持、変更有無による COM01008、編集モードから詳細表示への復帰が定義されている。
  - 実装: [単体テスト仕様書‗役職情報詳細.csv](単体テスト/単体テスト仕様書‗役職情報詳細.csv) には編集ボタン押下とキャンセルボタン押下のケースがなく、No.8 の戻るボタンは詳細/編集モードの復帰仕様を検証していない。
- 指摘内容:
  - 詳細表示から編集モードへの切り替え、履歴非表示、更新/キャンセル表示、変更不可項目の入力不可維持が未確認である。
  - キャンセル押下時の未変更/変更ありの両分岐がなく、COM01008 の確認と処理中断・復帰動作を確認できない。
- 期待されるテスト:
  - 編集ボタン押下で編集モードに切り替わり、履歴が非表示になること
  - 変更不可項目が新規登録時のみ編集可能で、編集モードでは編集不可のままであること
  - 変更ありでキャンセルした場合に COM01008 が表示され、キャンセル時は処理が中断されること
  - 変更なしでキャンセルした場合に詳細表示へ戻ること

### 5. 追加情報エリアの動的生成と入力チェックが不足
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗役職情報詳細.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) では、追加情報エリアは「役職情報項目定義」とコードグループマスター／コードマスターから動的生成され、変更不可設定の項目は新規登録モード時のみ入力可能とされている。また、追加情報入力チェック内容として略称、OBIC役職、電子承認役職コードの必須・文字数条件が定義されている。
  - 実装: [単体テスト仕様書‗役職情報詳細.csv](単体テスト/単体テスト仕様書‗役職情報詳細.csv) の No.30 は JSON 保存のみで、No.23〜No.26 は基本情報の重複入力に近い記載であり、動的生成、各追加情報項目の必須・文字数、入力タイプ、変更不可制御を確認していない。
- 指摘内容:
  - 追加情報の表示項目が定義どおり生成されること、参照コードグループから選択肢が作られること、変更不可項目の編集可否がモードで切り替わることが未確認である。
  - 追加情報入力チェックの観点が項目単位で不足しており、設計で定義された必須・文字数・入力タイプの確認ができない。
- 期待されるテスト:
  - 役職情報項目定義に基づいて追加情報の項目と入力欄が生成されること
  - 参照コードグループのコードからプルダウン選択肢が生成されること
  - 略称、OBIC役職、電子承認役職コードの必須・文字数チェックを個別に確認すること
  - 変更不可項目が新規登録モード以外では編集不可であること

### 6. 成功系の期待結果が具体不足
- 優先度: Low
- 種別: 記載不足
- 対象: 単体テスト仕様書‗役職情報詳細.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/070.組織情報/役職情報詳細.md](spec/基本設計/機能設計/070.組織情報/役職情報詳細.md) の登録・更新では、完了メッセージ COM01004、詳細表示へのリフレッシュ、登録時の有効終了日 9999/12/31、操作ログ記録が定義されている。
  - 実装: [単体テスト仕様書‗役職情報詳細.csv](単体テスト/単体テスト仕様書‗役職情報詳細.csv) の No.3、No.6 は「完了メッセージ」「DB 更新」止まりで、固定値の有効終了日や操作ログ、更新後の再表示結果まで期待結果が具体化されていない。
- 指摘内容:
  - 成功時の期待結果が粗く、設計どおりのデータ補正や画面再表示を確認できない。
- 期待されるテスト:
  - 登録時に有効終了日が 9999/12/31 で保存されること
  - 完了メッセージ COM01004 が表示されること
  - 更新後に詳細表示へリフレッシュされること
  - 操作ログが記録されること

## 総評
詳細表示の0件・複数件、編集モード遷移、更新時の履歴分岐、追加情報の動的項目検証が不足しており、役職情報詳細の主要な分岐を十分に覆えていません。
特に更新時の履歴追加分岐はデータ整合性に直結するため、最優先でケース追加が必要です。
現状の項目表は成功系と一部の基本バリデーションに偏っており、設計で定義された画面モード別挙動と権限制御の確認が弱い状態です。
