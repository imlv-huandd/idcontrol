# 基本レイアウト レビュー結果

## 指摘事項

### 1. 権限エラー時の期待結果が曖昧で合否判定不能
- 優先度: High
- 種別: 記載不足
- 対象: 単体テスト仕様書‗基本レイアウト.csv（No.21, 22, 23, 25-37）
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md の「機能名は権限を持つ場合のみ表示」「機能名クリックで対象画面へ遷移」。権限制御は結果が一意に定義されるべき。
  - 実装: 実装ファイル未提示のため未確認（アクセス拒否時のUI/HTTPステータス/遷移先の実装定義を確認できず）。
- 指摘内容:
  - 期待結果が「アクセス拒否またはエラー画面」となっており、2通りを許容しているため、仕様逸脱でもテストが通ってしまう。
  - 認可の単体テストとして、拒否時の振る舞い（表示文言、遷移先、HTTPステータス、トースト有無）が特定されていない。
- 期待されるテスト:
  - 拒否時の結果を一意に固定したケース（例: 403画面表示、対象画面DOMが描画されない、URLが遷移しない）。
  - APIレスポンスと画面挙動の両面確認（HTTP 403 / 401 とUI表示の整合）。

### 2. 権限別メニュー表示ケースが1ケース多観点で粒度不足
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗基本レイアウト.csv（No.5-9）
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md の「ログインユーザーの権限に応じて、使用可能な機能のみを表示」「機能が一つも表示されていない場合は機能分類を表示しない」。
  - 実装: 実装ファイル未提示のため未確認（メニュー生成ロジックの分岐単位を確認できず）。
- 指摘内容:
  - 1ケースに多数の機能分類・機能名リンクが詰め込まれており、どの分類/リンクで不整合が発生したか切り分けできない。
  - 「表示される」と「非表示」の確認が混在し、失敗原因の特定が困難。
- 期待されるテスト:
  - 1ケース1観点で分割（例: 役割×機能分類単位、役割×機能名単位）。
  - 少なくとも「分類表示可否」「配下リンク表示可否」「分類丸ごと非表示」を個別ケース化。

### 3. URL直接アクセスの許可系が機能分類単位で粗く、機能URL単位の保証が不足
- 優先度: Middle
- 種別: 項目不足
- 対象: 単体テスト仕様書‗基本レイアウト.csv（No.20, 24）
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md の「機能名クリックで各機能画面へ遷移」「権限に応じた機能利用」。判定対象は機能分類ではなく各機能URL。
  - 実装: 実装ファイル未提示のため未確認（ルーティングガードがURL単位か分類単位か確認不可）。
- 指摘内容:
  - 許可ケースが「機能分類のURL」としてまとめられており、分類内の各画面URL（検索/編集/設定等）の許可判定が個別に検証されていない。
  - 異常系はURL単位で細かい一方、正常系が粗く、権限マトリクスの片側のみ詳細になっている。
- 期待されるテスト:
  - 許可対象を機能URL単位で列挙した正常系ケース（少なくとも各分類から代表1件ではなく、権限表に記載された全URL）。
  - 許可対象URLで画面初期表示まで到達できること（タイトル/主要要素表示）を確認。

### 4. 依存先異常時の挙動テストが不足
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗基本レイアウト.csv（全体）
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md の「初期表示でログインユーザーの権限を取得」。
  - 実装: 実装ファイル未提示のため未確認（権限取得失敗時のハンドリング、全画面API失敗時処理を確認できず）。
- 指摘内容:
  - 権限情報取得失敗（通信失敗、401/403、タイムアウト）時のケースがなく、画面が不正状態で表示されるリスクを検証できない。
  - 全画面切替API非対応/拒否時のエラーハンドリングが未確認。
- 期待されるテスト:
  - 初期表示時の権限取得失敗ごとの挙動（エラー表示、ログイン画面遷移、リトライ可否）。
  - 全画面API失敗時にUIが不整合にならないこと（アイコン状態・表示状態維持）。

### 5. 前提条件の記述が不足し再現性が低いケースがある
- 優先度: Low
- 種別: 記載不足
- 対象: 単体テスト仕様書‗基本レイアウト.csv（No.11-17 ほか）
- 根拠:
  - 設計書: spec/基本設計/機能設計/010.システム共通/基本レイアウト.md のイベント詳細（表示切替、折り畳み/展開、全画面切替）。
  - 実装: 実装ファイル未提示のため未確認（画面サイズやブラウザ差異への依存有無を確認不可）。
- 指摘内容:
  - 一部ケースで対象機能分類、操作対象要素、確認手段（DOM/CSSクラス/URL）が明記されておらず、担当者によって判断がぶれる。
- 期待されるテスト:
  - 操作対象を具体化（どの機能分類をクリックするか、どのリンクを使うか）。
  - 期待結果を観測可能な値で記載（CSSクラス付与、要素表示有無、URL変化）。

## 総評
- 権限制御の観点は量としては多いものの、認可エラー時の期待結果が曖昧で、セキュリティ上の判定精度に課題があります。
- 役割別表示・URL直接アクセスの正常系が粗く、権限マトリクスを仕様どおりに保証しきれません。
- 依存先異常（権限取得失敗、全画面API失敗）の不足があり、運用時障害の検出力が弱い構成です。
- 優先順位は High（拒否時期待結果の明確化）→ Middle（粒度分割・依存異常）→ Low（記載詳細化）です。
