# マスターデータ 任意項目管理の仕組み

## 概要
本システムでは、マスターデータ（組織情報、就業者情報）に対して、テナントごとに任意の項目を追加できる柔軟な仕組みを提供する。
これにより、各テナントの業務要件に応じた独自の属性を管理することが可能となる。

## アーキテクチャ

### 基本設計方針
- **項目定義とデータの分離**: 任意項目の定義情報と実際のデータを分離して管理
- **JSONB型の活用**: PostgreSQLのJSONB型を利用し、柔軟かつ効率的にデータを格納
- **スキーマレス設計**: 項目の追加・削除時にテーブル構造の変更が不要

### データモデル構成

```
┌─────────────────────────┐
│  属性項目定義テーブル     │  ← 任意項目のメタデータを管理
│  (attribute tables)     │     (項目名、型、必須フラグ等)
└─────────────────────────┘
            │
            │ 項目定義を参照
            ▼
┌─────────────────────────┐
│  マスターデータテーブル   │  ← 実際のデータをJSONBで格納
│  (master tables)        │     (attr カラムに全任意項目の値)
└─────────────────────────┘
```

## 就業者情報を例にした任意項目管理の概要

### 1. 就業者属性項目テーブル (`person_attribute`)
就業者情報で管理する任意項目の定義を保持する。

| 項目名               | 項目物理名         | 型名         | 説明                                                               |
| -------------------- | ------------------ | ------------ | ------------------------------------------------------------------ |
| テナントID           | tenant_id          | UUID         | テナントを一意に識別するID                                         |
| 項目ID               | person_column_id   | varchar(100) | 就業者属性のキー名（例: "employee_type", "hire_date"）             |
| 項目名称             | person_column_name | varchar(100) | 画面表示用の項目名（例: "雇用形態", "入社日"）                     |
| 必須                 | not_empty          | bool         | 項目の入力必須フラグ                                               |
| 入力タイプ           | input_type         | char(64)     | "STRING", "DATE", "DATETIME"のいずれか                             |
| 参照コードグループID | code_group_id      | UUID         | 入力タイプがSTRINGの場合の選択肢を定義するコードグループID（任意） |
| 最大文字数           | max_length         | int          | STRING型の場合の最大文字数                                         |
| 表示順               | order              | int          | 画面表示時の項目順序                                               |
| 項目説明             | description        | varchar(200) | 項目の説明テキスト                                                 |

**設定例**:
```sql
-- 雇用形態（コード選択式）
INSERT INTO person_attribute VALUES (
  '019b2ab3-ca94-7e38-806b-1423d4f5d8ce', -- テナントID
  'employee_type', -- 項目ID
  '雇用形態', -- 項目名
  true, -- 必須
  'STRING', -- 入力タイプ
  NULL, -- 参照コードグループID
  50,
  1,
  '正社員、契約社員、派遣社員等の雇用形態'
);

-- 入社日（日付）
INSERT INTO person_attribute VALUES (
  '019b2ab3-ca94-7e38-806b-1423d4f5d8ce',
  'hire_date',
  '入社日',
  true,
  'DATE',
  NULL,
  NULL,
  2,
  '従業員の入社年月日'
);
```

### 2. 就業者情報テーブル (`person`)
実際の就業者データを保持し、任意項目の値は `person_attr` カラム（JSONB型）に格納される。

| 項目名           | 項目物理名       | 型名         | 説明                             |
| ---------------- | ---------------- | ------------ | -------------------------------- |
| テナントID       | tenant_id        | UUID         | テナントを一意に識別するID       |
| 就業者ID         | person_id        | UUID         | 就業者を一意に識別するID         |
| テナント就業者ID | tenant_person_id | varchar(100) | 社員番号等の人が識別する文字列   |
| 基準日           | base_date        | date         | この就業者属性が適用される基準日 |
| 最終更新媒体     | latest_medium    | varchar(100) | 最終更新元システム名             |
| 苗字             | last_name        | varchar(100) | 苗字                             |
| 名前             | first_name       | varchar(100) | 名前                             |
| 退職日           | retire_date      | date         | 退職日（在職中の場合NULL）       |
| **就業者属性**   | **person_attr**  | **jsonb**    | **任意項目の値を格納するJSON**   |

**person_attr カラムの仕様**:
```json
{
  "employee_type": "正社員",  // 項目ID: 設定値
  "hire_date": "2020-04-01", // 項目ID: 設定値
}
```
- キー名は `person_attribute.person_column_id` と一致する
- オブジェクトや配列は格納しない（プリミティブ値のみ）

## 任意項目編集上の対応方針

### 1. 項目追加時
1. 属性項目テーブルにレコードを追加
2. 既存のマスターデータの更新はしない（JSONBに該当キーがない状態とする）。必須項目として追加した場合も行わない。

### 2. 項目設定変更時
1. 現在の項目値は、項目定義に合わせて更新されないことをユーザーに通知
2. 属性項目テーブルのレコードを更新
3. 既存のマスターデータの更新はしない。必須項目として追加した場合も行わない。

### 3. 項目削除時
. 属性項目テーブルからレコードを削除
2. マスターデータのJSONBから該当キーを削除する（残すと同名キーが新たに追加された場合に過去データが出てきてしまう為。）

## システム連携での活用

### 連携元システムからのマッピング
連携元インターフェイスの項目を任意項目にマッピングする際、`interface_to_master_mapping` テーブルで設定する。

**マッピング例**:
```json
{
  "mapping": [
    {
      "setMethod": "PROCESS",
      "baseColumn": "019b1034-486f-73a7-8d7c-7d712c5718b9",
      "convertMethod": "NONE",
      "conditions": []
    }
  ]
}
```
- `baseColumn` には連携元インターフェイス項目のIDを指定
- マッピング先の項目IDは `interface_to_master_mapping.person_column_id` に設定

### 連携先システムへのマッピング
任意項目を連携先インターフェイスにマッピングする際、`master_to_interface_mapping` テーブルで設定する。

**マッピング例**:
```json
{
  "settings": [
    {
      "setMethod": "PROCESS",
      "baseColumn": "employee_type",
      "convertMethod": "NONE",
      "conditions": []
    }
  ]
}
```
- `baseColumn` には任意項目のID（`person_column_id` または `org_column_id`）を指定
