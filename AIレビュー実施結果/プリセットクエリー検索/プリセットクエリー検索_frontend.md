# プリセットクエリー検索 レビュー結果

## 指摘事項

### 1. 新規登録・編集イベントが未実装で、設計必須の画面遷移を満たしていない
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/queries/PresetQueries.jsx, frontend/src/App.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/080.プリセットクエリー/プリセットクエリー検索.md の「イベント定義 No.4 新規登録ボタン押下」「No.6 編集ボタン押下」で、マスター検索／プリセットクエリー編集画面への遷移を要求。
  - 実装: frontend/src/pages/queries/PresetQueries.jsx の handleNew, handleEdit が空実装。frontend/src/App.jsx にプリセットクエリー編集画面のルート定義が確認できない。
- 指摘内容:
  - 画面仕様上の主要導線（新規登録・編集）が機能しないため、機能要件未達。
- 期待されるテスト:
  - 新規登録ボタン押下で新規モード遷移すること。
  - 編集ボタン押下で対象クエリーIDを引き継いで編集モード遷移すること。
  - ルーティング未定義時に検知できる結合テストを追加すること。

### 2. 「テナント管理者専用」要件に対するフロント表示制御が未実装
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/queries/PresetQueries.jsx, frontend/src/App.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/080.プリセットクエリー/プリセットクエリー検索.md の「機能概要」でテナント管理者専用機能、項目定義で新規登録ボタンは「ログインユーザーがテナント管理者の場合のみ表示」。
  - 実装: frontend/src/pages/queries/PresetQueries.jsx で新規登録ボタンを常時表示しており、権限に応じた表示/非表示条件分岐がない。frontend/src/App.jsx の /preset-queries ルートにも認証・認可ガードがない。
- 指摘内容:
  - 権限外ユーザーにも管理操作導線が見える状態で、設計逸脱。さらに画面到達自体の制御がないため、サーバ側拒否だけでは要件を満たさない。
- 期待されるテスト:
  - テナント管理者では新規登録ボタンが表示されること。
  - テナント管理者以外では新規登録ボタンが非表示であること。
  - 未認可ユーザーが /preset-queries に直接アクセスした場合に、アクセス拒否または遷移制御されること。

### 3. 検索APIにテナント管理者チェックが見当たらず、専用機能要件と不整合
- 優先度: High
- 種別: 設計確認事項
- 対象: functions/presetQueries/searchPresetQueries/app.py, shared/services/presetQuerieService.py
- 根拠:
  - 設計書: spec/基本設計/機能設計/080.プリセットクエリー/プリセットクエリー検索.md の機能概要・バリデーション定義でテナント管理者チェック(COM01001)を要求。
  - 実装: functions/presetQueries/searchPresetQueries/app.py と shared/services/presetQuerieService.py の検索処理に、削除処理相当の権限チェック実装が確認できない（削除側には COM01001 チェックあり）。
- 指摘内容:
  - フロントから検索APIを直接呼べるため、API側での権限制御欠落は認可不備リスク。画面制御だけでは防げない。
- 期待されるテスト:
  - 権限なしユーザーで検索APIを呼んだ場合に COM01001 になること。
  - 権限ありユーザーで正常検索できること。

### 4. 検索失敗時のエラー状態を保持しているが画面に表示していない
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/queries/PresetQueries.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/080.プリセットクエリー/プリセットクエリー検索.md のイベント詳細（検索/削除）ではメッセージ表示前提で操作結果を通知する仕様。
  - 実装: frontend/src/pages/queries/PresetQueries.jsx で search 失敗時に setError は実行しているが、error state を描画しておらず利用者に失敗理由が提示されない。
- 指摘内容:
  - 通信失敗・API失敗時のユーザー通知が不足し、再試行判断ができない。
- 期待されるテスト:
  - 検索APIが 4xx/5xx を返した場合にエラーメッセージが表示されること。

### 5. 削除後再検索が「最後に実行した条件」ではなく入力中条件を参照している
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/queries/PresetQueries.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/080.プリセットクエリー/プリセットクエリー検索.md の削除ボタン押下で「現在のページで検索を再実行し、一覧を更新」と定義。
  - 実装: frontend/src/pages/queries/PresetQueries.jsx の handleDeleteConfirm で再検索条件に state の presetQueryName を直接利用。検索後に入力欄のみ変更した場合、表示中一覧の条件と不一致の再検索が起こり得る。
- 指摘内容:
  - 仕様上の「現在の一覧を基準に再検索」とずれる可能性があり、削除後の一覧が利用者の認識と不一致になる。
- 期待されるテスト:
  - 検索実行後に入力欄を変更しても、削除後再検索は最後に実行した検索条件で行われること。

## 総評
本機能は検索と削除の基本動作は実装されている一方、設計必須の新規登録/編集遷移が未実装であり、リリース可否に直結する High 指摘が存在します。
また、テナント管理者専用要件に対するフロント表示制御不足と、検索API側権限チェック不整合は認可観点の品質リスクです。
修正優先順位は、1) 新規/編集導線実装、2) 権限制御整合（UI/API）、3) エラー表示と再検索条件の是正、4) 単体テスト整備の順が妥当です。

- spec/詳細設計 配下に本機能の詳細処理記述が存在する場合の突合は未実施（ユーザー指定設計書を主対象としてレビュー）。
