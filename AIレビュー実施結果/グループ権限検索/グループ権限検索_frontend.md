# グループ権限検索 レビュー結果

## 指摘事項

### 1. 検索実行時に現在ページを1ページ目へリセットしていない
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/permissions/GroupPermissionSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/050.権限管理/グループ権限検索.md の「検索ボタン押下」で「ページネーションの現在ページを1ページ目に設定する」と定義。
  - 実装: GroupPermissionSearch.jsx では `handleSearch` 内で `loadGroupPermissions(..., 1)` を実行しているが、`setCurrentPage(1)` が呼ばれていない。`currentPage` は `Pagination` にそのまま渡されるため、表示上の現在ページが前回検索時の値のまま残る。
- 指摘内容:
  - データ取得ページは1ページ目でも、ページネーション表示の現在ページが旧値のままになる可能性があり、仕様の「現在ページを1ページ目に設定」に未達。
- 期待されるテスト:
  - 別条件で再検索した際、データ取得ページとページネーション表示の両方が1ページ目になること。
  - 3ページ目表示中に検索条件を変更して検索した場合でも、1ページ目表示へ戻ること。

### 2. 検索失敗時のエラーメッセージを画面表示していない
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/permissions/GroupPermissionSearch.jsx
- 根拠:
  - 設計書: ユーザー確認項目（API連携・エラー表示）に照らし、異常時に利用者へ失敗理由を通知できることが必要。
  - 実装: `error` state を定義し、`catch` で `setError(...)` しているが、JSX内に `error` を表示する要素が存在しない。
- 指摘内容:
  - 通信失敗時に利用者が失敗理由を確認できず、再試行判断や問い合わせ時の情報が不足する。
- 期待されるテスト:
  - APIが 4xx/5xx を返した場合にエラーメッセージが表示されること。
  - ネットワークエラー時に既存結果表示とエラー表示の整合が取れていること。

### 3. 連携システム権限の表示形式が設計の文言と不一致
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/permissions/GroupPermissionSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/050.権限管理/グループ権限検索.md の項目定義に「連携システム管理者、連携システム操作者権限は、末尾に"（【連携システム名】）"を付与する」と定義。
  - 実装: `getPermissionDisplay` は `"権限ラベル: systemDisplayName"` 形式（コロン区切り、グレー文字）で描画しており、括弧付き文言形式になっていない。
- 指摘内容:
  - 設計で定義された表示ルールと実画面の文言形式が一致していない。
- 期待されるテスト:
  - `RELATION_SYSTEM_ADMIN` / `RELATION_SYSTEM_USER` の各表示が「権限表示名（【連携システム名】）」形式になること。
  - `systemDisplayName` が空の場合のフォールバック表示が仕様通りであること。

### 4. jQuery/select2 未初期化時の再試行が無制限で、タイマー解放もしていない
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/permissions/GroupPermissionSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/050.権限管理/グループ権限検索.md では選択UI要件のみ定義されるが、可用性を損なう実装（無限再試行）は想定されていない。
  - 実装: `initSelect2` の `else` で `setTimeout(initSelect2, 100)` を無制限実行し、cleanupで timeout id を clear していない。
- 指摘内容:
  - jQuery/select2 読み込み失敗時に再試行が止まらず、ログ増大・不要なタイマー実行が継続するリスクがある。
- 期待されるテスト:
  - select2 未ロード時に再試行回数上限や打ち切り条件で安全停止すること。
  - コンポーネント unmount 後に再試行タイマーが残らないこと。

### 5. グループ名昇順ソートの担保がフロントエンド上で確認できない
- 優先度: Low
- 種別: 設計確認事項
- 対象: グループ権限検索（表示順制御）
- 根拠:
  - 設計書: spec/基本設計/機能設計/050.権限管理/グループ権限検索.md で「ソート順はグループ名の昇順」と定義。
  - 実装: GroupPermissionSearch.jsx 側でソート処理は行っておらず、APIレスポンス順をそのまま表示している。
- 指摘内容:
  - 昇順担保をAPI側責務とする前提の明文化が必要。現状のフロント単体では設計要件を満たしているか判定不能。
- 期待されるテスト:
  - API契約テストまたは結合テストで、返却データが常にグループ名昇順であること。

### 6. フロントエンド単体テストが未作成で、単体テスト観点を満たしていない
- 優先度: Middle
- 種別: テスト不足
- 対象: frontend/src/pages/permissions/GroupPermissionSearch.jsx（および関連コンポーネント）
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md の「単体テスト観点」に 正常系 / 入力値バリエーション / 境界値 / 分岐条件 / データ入出力 / 非更新確認 / 異常系 が定義。
  - 実装: 対象機能のフロントエンドテストコード（.test/.spec）が存在しない。
- 指摘内容:
  - 仕様検証の自動化がなく、分岐・異常系・表示ルール逸脱の検知ができない。
- 期待されるテスト:
  - 正常系: 初期表示（結果・ページング非表示）、検索成功時の一覧表示。
  - 入力値バリエーション: グループ名未入力/部分一致、権限0件/1件/複数件選択。
  - 境界値: 0件、20件、21件でのページング表示有無と表示件数。
  - 分岐条件: 権限なし/あり、所属ユーザーなし/あり、連携システム権限表示分岐。
  - データ入出力: APIパラメータ生成（groupName/permissions/page/pageSize）と表示内容の一致。
  - 非更新確認: クリア実行で検索結果エリアが非表示に戻ること、検索条件のみが初期化されること。
  - 異常系: API失敗時のエラー表示、ローディング解除、再操作可能状態への復帰。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足
  - 初期表示（結果・ページング非表示）、検索成功時表示、編集遷移の基本フロー自動テストが未整備。
- 入力値バリエーション不足
  - グループ名の空/部分一致、権限未選択/単一/複数選択の組み合わせ網羅が未整備。
- 境界値不足
  - 0件、20件、21件時のページング表示境界の検証が未整備。
- 分岐条件不足
  - 連携システム権限表示、未設定表示（所属ユーザーなし）など表示分岐の検証が未整備。
- データ入出力不足
  - 画面条件→APIクエリ→一覧表示内容の整合検証が未整備。
- 非更新確認不足
  - クリアで結果非表示、再検索でページ1復帰など状態遷移の非更新確認が未整備。
- 異常系不足
  - APIエラー、ネットワークエラー時の画面挙動（エラー通知・ローディング解除）検証が未整備。

## 総評
Middle優先の指摘として、ページ状態のリセット不備、エラー表示欠落、権限表示形式の設計不一致を確認しました。
現状は重大障害直結ではないものの、利用者体験と仕様適合性の観点でリリース前に是正した方が安全です。
加えてフロント単体テスト未整備のため、仕様逸脱の再発検知ができない状態です。
修正優先は「ページ状態」「エラー表示」「表示形式」→「テスト整備」の順を推奨します。
