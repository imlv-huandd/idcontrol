# 就業者検索 レビュー結果

## 指摘事項

### 1. 就業者詳細ボタンが選択履歴を正しく開けない
- 優先度: High
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/060.就業者情報/就業者検索.md の「就業者詳細ボタン押下」では、クリックした行の就業者を詳細表示モードで開くことが求められている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx では詳細ボタン押下時に startDate に w.validFrom、endDate に w.validTo を設定しているが、searchPersons のレスポンス項目は startDate / endDate であり一致していない。frontend/src/pages/workers/WorkerDetail.jsx では startDate / endDate を使って表示対象履歴を選択しているため、undefined が渡ると詳細情報が表示されない。
- 指摘内容:
  - 一覧から就業者詳細を開く主要導線が、レスポンス項目名の不一致により実質的に壊れている。personId だけでは表示対象履歴を選べず、設計通りの「クリックした行の就業者詳細表示」が成立しない。
- 期待されるテスト:
  - 検索結果の1行目で就業者詳細ボタンを押下したとき、対象行の開始日・終了日に対応する履歴が詳細モーダルに表示されること。
  - 複数履歴を持つ就業者で、押下した行の履歴が選択されること。

### 2. CSV出力の0件時・権限エラー時の画面制御が設計と不一致
- 優先度: High
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/060.就業者情報/就業者検索.md の「CSV出力ボタン押下」では、0件時は COM01003 をダイアログ表示して終了し、権限不足時は COM01001 をダイアログ表示して終了するとされている。
  - 設計書: spec/詳細設計/openapi/paths/persons.yaml では CSV 出力 API は CSV 応答とエラー応答の契約が分かれている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx の handleCSVExport は HTTP 200 をすべて blob としてダウンロードし、非200時もレスポンス本文の message/code を読まずに HTTP ステータス文字列だけを表示している。functions/persons/createPersonCsv/app.py は0件時に message=COM01003 を返し、権限不足時は403を返す実装である。
- 指摘内容:
  - 0件時に JSON メッセージを CSV ファイルとして誤ってダウンロードする可能性がある。
  - 権限不足や業務エラー時に設計で要求されるメッセージダイアログが出ず、利用者は原因を判別しにくい。
- 期待されるテスト:
  - CSV出力対象が0件のとき、ダウンロードせず COM01003 相当のメッセージを表示すること。
  - ダウンロード権限がないとき、ダウンロードせず COM01001 相当のメッセージを表示すること。
  - 正常時のみ CSV ファイルがダウンロードされること。

### 3. 所属詳細ボタンと出力設定ボタンが常時非活性で未実装
- 優先度: High
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/060.就業者情報/就業者検索.md のイベント定義では、所属詳細ボタン押下で就業者所属情報詳細画面へ、連携設定ボタン押下で就業者連携データ出力設定画面へ遷移すると定義されている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx では「所属詳細」「出力設定」ボタンが disabled 固定となっており、遷移処理も存在しない。
- 指摘内容:
  - 設計上の必須イベントが画面から実行できず、検索結果から次画面へ進めない。主要機能の欠落であり、レビュー対象機能として未完了。
- 期待されるテスト:
  - 各行の所属詳細ボタン押下で対象就業者IDを引き継いで所属詳細画面へ遷移すること。
  - 各行の出力設定ボタン押下で対象就業者IDを引き継いで出力設定画面へ遷移すること。

### 4. 検索ボタン押下時に現在ページが1ページ目へ戻らない
- 優先度: Middle
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/060.就業者情報/就業者検索.md の「検索ボタン押下」では、ページネーションの現在ページを1ページ目に設定すると定義されている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx の handleSearch は page 引数未指定時に currentPage をそのまま使うため、利用者が2ページ目以降で条件変更して再検索しても同じページ番号で問い合わせる。
- 指摘内容:
  - 条件変更後の再検索で後続ページを直接取得してしまい、先頭ページの結果を見落とす。結果件数が少ない条件では空ページに見える可能性もある。
- 期待されるテスト:
  - 3ページ目表示中に検索条件を変更して検索したとき、1ページ目の結果が表示されること。
  - ページ変更操作時だけ指定ページで再検索されること。

### 5. 一覧表示が設計の表示ルールを満たしていない
- 優先度: Middle
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/060.就業者情報/就業者検索.md の検索結果エリアでは、有効終了日は 9999/12/31 の場合のみ非表示、組織名称・役職名称は複数件を改行区切り、所属情報がない場合は「（未設定）」と表示すると定義されている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx では有効終了日を retireDate がある場合だけ表示しており、9999/12/31 判定になっていない。orgName / positionName はそのまま1値表示で、未設定時の代替表示や改行整形もない。
- 指摘内容:
  - 退職していないが終了日を持つデータの有効終了日が画面に出ない。
  - 所属なしデータが空欄表示になり、設計上の「（未設定）」が表示されない。
  - 複数所属・複数役職を想定した改行区切り表示にも対応していない。
- 期待されるテスト:
  - endDate が 9999/12/31 以外かつ retireDate 未設定のデータで有効終了日が表示されること。
  - 所属情報なしのデータで「（未設定）」が表示されること。
  - 複数組織名・複数役職名が改行区切りで表示されること。

### 6. 組織名称・役職名称のサジェスト入力が未実装
- 優先度: Middle
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/060.就業者情報/就業者検索.md の項目定義では、組織名称（表示名）と役職名称は入力内容に部分一致する候補をサジェスト表示すると定義されている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx では両項目とも通常のテキスト入力のみで、候補取得や候補一覧表示の処理が存在しない。
- 指摘内容:
  - 画面仕様で定義された補助入力機能が欠落している。検索自体はできても、候補選択前提の利用性と入力精度を満たせていない。
- 期待されるテスト:
  - 組織名称の部分入力時に一致候補が表示されること。
  - 役職名称の部分入力時に一致候補が表示されること。
  - 候補選択後にその値で検索されること。

### 7. 検索基準日の入力エラーを検索・CSV出力前に止められない
- 優先度: Middle
- 種別: 実装不備
- 対象: WorkerSearch.jsx
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md では、入力値バリエーション、境界値、異常系の観点で不正入力時の結果を具体的に確認することが求められている。
  - 実装: frontend/src/pages/workers/WorkerSearch.jsx は handleDateBlur で validateDate の結果を error state に入れるが、handleSearch / handleCSVExport は処理開始時に error をクリアしてそのままAPI呼び出しを継続する。さらに API エラーと日付エラーが同じ error state を共有している。
- 指摘内容:
  - 利用者に日付エラーが見えていても検索・CSV出力を実行でき、不正な検索基準日が送信される。
  - 日付入力エラーと通信エラーが同じ表示領域に混在するため、どの項目が誤っているか判別しにくい。
- 期待されるテスト:
  - 存在しない日付や不正形式の日付入力時に検索・CSV出力が実行されないこと。
  - 日付エラー表示と API エラー表示が混在せず、入力欄ごとに判別できること。

### 8. フロントエンド単体テストが未作成で主要仕様が未検証
- 優先度: Middle
- 種別: テスト不足
- 対象: 就業者検索
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md の単体テスト観点では、正常系、入力値バリエーション、境界値、分岐条件、データ入出力、非更新確認、異常系を対象機能ごとに網羅することが求められている。
  - 実装: フロントエンドの就業者検索に対応するテストコードはワークスペース内で確認できなかった。検索、ページング、CSV出力、詳細遷移、入力バリデーションの各分岐が未検証である。
- 指摘内容:
  - 主要導線である検索、CSV出力、詳細表示、ページング、入力エラー表示の回帰を検知できない。
  - 現在の実装不備が自動検知されず、今後の修正時にも同種の不具合を再混入させるリスクが高い。
- 期待されるテスト:
  - 正常検索、0件検索、ページング再検索、クリア、CSV正常出力、CSV 0件、CSV権限不足、就業者詳細遷移、所属詳細遷移、出力設定遷移、検索基準日の正常/異常入力を最低限追加すること。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足: 初期表示、条件指定検索、0件表示、クリア、ページング、CSV正常出力、就業者詳細表示、所属詳細遷移、出力設定遷移のテストがない。
- 入力値バリエーション不足: テナント就業者ID・姓・名・かな・組織名称・役職名称の未入力、部分一致、複数条件組み合わせ、退職済チェックON/OFFのテストがない。
- 境界値不足: 検索基準日の未入力、月末日付、存在しない日付、9999/12/31、有効終了日ありかつ退職日なし、ページ境界（1ページ目、最終ページ）のテストがない。
- 分岐条件不足: includeRetired のON/OFF、検索結果あり/なし、CSV 200/403/404/500、詳細モーダルの新規登録/詳細表示、履歴あり/なしの分岐が未検証である。
- データ入出力不足: テナント設定から personColumnName を取得して画面見出しに反映すること、検索結果の表示整形、CSVダウンロード開始条件の検証がない。
- 非更新確認不足: クリア押下で検索実行されないこと、不正日付入力時に検索・CSV出力が走らないこと、0件CSV時にファイルが生成されないことの確認がない。
- 異常系不足: テナント設定取得失敗、検索API失敗、CSV出力API失敗、権限不足、エラーメッセージ表示のテストがない。

## 総評
- High 指摘は、就業者詳細の表示不全、CSV出力の誤処理、所属詳細/出力設定の未実装であり、主要導線の成立性に直接影響する。
- Middle 指摘として、検索再実行時のページ制御、一覧表示ルール、サジェスト、日付入力エラー処理、未作成のテストが残っている。
- まずは High 指摘の修正と、それを固定する最小限の画面テスト追加を優先すべきである。
