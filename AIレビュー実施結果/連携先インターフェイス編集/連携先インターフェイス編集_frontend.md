# 連携先インターフェイス編集 レビュー結果

## 指摘事項

### 1. 削除ボタンが選択行ではなくテーブル全体を渡しており、未選択時のエラー制御と確認内容が設計通りに動作しない
- 優先度: High
- 種別: 実装不備
- 対象: TargetIntegrationInterface.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「キー項目削除ボタン押下」「入力項目削除ボタン押下」「出力項目削除ボタン押下」で、選択行がない場合は IFC06003 を表示し、選択行がある場合のみ削除確認を出すこと、確認ダイアログには削除対象名を表示することが定義されている。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx のキー項目・入力項目・出力項目の削除ボタンは handleDeleteRows に selectedRows ではなく keyItemDefinition / inputItemDefinition / outputItemDefinition を渡している。一方 handleDeleteRows 側は引数の length を見て未選択判定しており、確認ダイアログの detail も組み立てていない。
- 指摘内容:
  - 未選択でもテーブル行が1件以上あれば確認ダイアログに進むため、設計で要求されている「未選択時は IFC06003 を表示して終了」が成立していない。
  - さらに削除対象名の詳細表示も実装されていないため、削除確認の内容が設計不足となっている。
- 期待されるテスト:
  - キー項目・入力項目・出力項目それぞれで、未選択時に IFC06003 が表示され確認ダイアログが出ないこと。
  - 選択あり時に削除対象名を含む確認ダイアログが表示され、確定後に選択行のみ削除されること。

### 2. 出力設定候補再構築が設計未達で、存在しない項目を優先度判定条件に保持したまま送信できる
- 優先度: High
- 種別: 実装不備
- 対象: TargetIntegrationInterface.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「出力設定候補再構築」で、キー項目定義・出力項目定義から候補を再構築し、既存選択値が候補に存在しない場合は未選択に戻すことが定義されている。バリデーション定義「出力設定入力チェック」でも、項目はキー項目または出力項目のいずれかであることが要求されている。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx の keyItemDefinition / outputItemDefinition 監視 useEffect は、columnId が空の行に firstOptionId を補うだけで、候補から外れた既存 columnId を未選択へ戻していない。さらに validatePrioritySettings には columnId 所属チェックの TODO が残っており、実質的に空欄以外を許容している。
- 指摘内容:
  - キー項目や出力項目を削除・変更した後でも、優先度判定条件に無効な columnId を保持できるため、設計上不正な選択値を送信できる。
  - 候補再構築の中核仕様とバリデーションの双方が未完了であり、優先度出力設定の整合性が担保されていない。
- 期待されるテスト:
  - 優先度判定条件で参照中のキー項目または出力項目を削除したとき、その行の項目が未選択へ戻ること。
  - 候補外の columnId を持つ状態では COM02009 で保存できないこと。

### 3. 編集モードでもキー項目の並び替えが可能で、変更不可のはずのキー定義を更新リクエストへ載せてしまう
- 優先度: Middle
- 種別: 実装不備
- 対象: TargetIntegrationInterface.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「キー項目追加ボタン押下」「キー項目削除ボタン押下」「キー項目行D&D」で、いずれも新規登録時のみ有効と定義されている。更新ボタン押下の仕様でも、通常/統合ともに更新対象は入力項目・出力項目・統合定義が中心で、キー項目変更は前提にされていない。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx のキー項目テーブル行は編集モードでも draggable のままで、handleDropKey に到達できる。加えて更新 API の body には keyColumns を含めている。
- 指摘内容:
  - UI 上は追加・削除・入力が無効でも、D&D によりキー項目順を変更できるため、編集モードで変更不可とした設計を破っている。
  - 更新 payload に keyColumns を含めているため、バックエンド実装次第では本来変更不可のキー定義が更新される余地がある。
- 期待されるテスト:
  - 編集モードではキー項目行をドラッグできず、順序が変わらないこと。
  - 編集モードの更新リクエストでキー定義が変更対象にならないこと。

### 4. 自身を候補から除外すべき前段インターフェイスと統合対象で、自分自身を選択できる画面になっている
- 優先度: Middle
- 種別: 実装不備
- 対象: TargetIntegrationInterface.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「初期表示（変更モード）」で、前段インターフェイス候補は同一システムかつ自インターフェイス以外、統合定義は自身を除くインターフェイスを表示すると定義されている。バリデーション定義でも自分自身の指定は禁止されている。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx の前段インターフェイス select は system.lowerInterfaces をそのまま列挙しており、自身除外をしていない。統合定義テーブルも listRelationSystems をそのまま描画しており、自身を候補から除外していない。さらに INTERFACE へ切り替えた際は先頭候補を prepareInterfaceId に自動設定している。
- 指摘内容:
  - 保存時バリデーションでは弾いていても、画面上で自分自身を候補表示・選択可能にしている時点で設計逸脱であり、誤操作を誘発する。
  - INTERFACE 切替時に未選択ではなく先頭候補を自動投入するため、設計の初期値とも一致していない。
- 期待されるテスト:
  - 編集モードで前段インターフェイス候補から自インターフェイスが除外されること。
  - 統合定義テーブルに自インターフェイスが表示されないこと。
  - INTERFACE 切替直後は未選択であり、明示選択が必要なこと。

### 5. 編集対象が存在しない場合の COM01009 表示と一覧遷移が実装されていない
- 優先度: Middle
- 種別: 実装不備
- 対象: TargetIntegrationInterface.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「初期表示（変更モード）」で、対象が存在しない場合は COM01009 を表示し、連携システム／インターフェイス一覧に遷移すると定義されている。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx の getLowerSystemInterface は fetch 失敗時に setError と loading 解除のみを行っており、COM01009 固定のハンドリングや navigate('/integration-systems') を実行していない。
- 指摘内容:
  - URL パラメータ不正や対象削除済みのケースで、設計上の復帰導線がなく、画面が中途半端なエラー状態で残る。
- 期待されるテスト:
  - 編集対象が存在しないレスポンス時に COM01009 が表示され、一覧画面へ遷移すること。
  - 初期表示 API の通信失敗時にローディングが解除され、ユーザーが復帰可能な導線があること。

### 6. フロントエンドの単体テストがなく、主要な表示分岐・入力チェック・活性制御が未検証のままになっている
- 優先度: Middle
- 種別: テスト不足
- 対象: 連携先インターフェイス編集
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md では、インターフェイス種別、連携タイミング種別、定義種別、出力種別ごとに表示エリアと活性状態が大きく分岐する。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx に対するフロントエンドテストコードは未作成前提であり、UI 分岐とバリデーションの回帰検知手段が存在しない。
- 指摘内容:
  - この画面は分岐数と入力項目数が多く、設計通りの表示/非表示、活性/非活性、必須チェックを人手確認だけで維持するのは困難である。
  - spec/050.テスト/テスト観点.md の単体テスト観点に照らすと、正常系、入力値バリエーション、境界値、分岐条件の最低限の担保が欠落している。
- 期待されるテスト:
  - 追加モード通常、追加モード統合、編集モード通常、編集モード統合の4大分岐の表示確認。
  - インターフェイス種別、連携タイミング種別、定義種別、出力種別の切替ごとの表示/活性制御確認。
  - 必須・形式・重複・範囲チェックのエラー表示確認。

### 7. 異常系と非更新確認のテストがなく、通信失敗や競合更新、変更なし更新の品質保証が不足している
- 優先度: Middle
- 種別: テスト不足
- 対象: 連携先インターフェイス編集
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「登録ボタン押下」「更新ボタン押下」「戻るボタン押下」では、権限エラー、対象なし、変更有無チェック、楽観ロックエラー、通信失敗時のメッセージ制御が重要な仕様として定義されている。
  - 単体テスト観点: spec/050.テスト/テスト観点.md の観点分類では、非更新確認不足、異常系不足、データ入出力不足を最低限確認すべきと整理されている。
  - 実装: 現状フロントエンドテストがなく、API 失敗、COM01009、COM01010、COM01011、IFC06001、IFC06004 などのエラー導線が未検証である。
- 指摘内容:
  - 実装不備が起きやすい初期表示失敗、変更なし更新、競合更新、自己参照禁止、統合対象不正などのケースが未検証で、回帰時に見逃しやすい。
- 期待されるテスト:
  - 初期表示 API 失敗、対象なし、競合更新、変更なし更新、削除未選択、自己参照、統合対象なしの各ケースで期待メッセージと遷移が正しいこと。
  - 戻るボタンで変更あり/変更なしの分岐が正しいこと。

### 8. 仕様値と初期値に軽微な不一致があり、設計書通りの入力条件になっていない
- 優先度: Low
- 種別: 実装不備
- 対象: TargetIntegrationInterface.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md の「種別設定入力チェック」ではファイル名は 300 文字以内、「出力設定エリア」では出力種別の初期値は差分と定義されている。
  - 実装: frontend/src/pages/integration/TargetIntegrationInterface.jsx の validateDetailSetting はファイル名上限を 100 文字で判定している。また lowerInterface 初期 state の outputType は FULL になっている。
- 指摘内容:
  - 正常な 101〜300 文字のファイル名を不当にエラーにする可能性がある。
  - 初期 state と設計初期値が一致しておらず、将来 UI 初期表示や送信条件に副作用を生む余地がある。
- 期待されるテスト:
  - ファイル名 100 文字、300 文字、301 文字の境界値テスト。
  - 追加モード初期表示時の出力種別初期値テスト。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足:
  - 追加モード通常、追加モード統合、編集モード通常、編集モード統合の各登録・更新フローの確認がない。
- 入力値バリエーション不足:
  - インターフェイス種別 5 パターン、連携タイミング種別 3 パターン、定義種別 2 パターン、出力種別 4 パターンの切替検証がない。
- 境界値不足:
  - インターフェイス名 100 文字、ファイル名 300 文字、オフセット日数 -99〜99、チェック起動時刻 0〜23、項目名 100 文字の境界値が未検証である。
- 分岐条件不足:
  - 連携しない時の非活性制御、統合時の入力項目非表示、優先度出力時の条件テーブル表示、自身除外候補表示の分岐が未検証である。
- データ入出力不足:
  - 優先度判定条件の候補再構築、D&D 後の再採番、更新 payload の内容、API エラー時のメッセージと遷移が未検証である。
- 非更新確認不足:
  - 変更なし更新時の COM01011、戻るボタンの変更有無分岐、編集モードで変更不可項目が送信されないことの確認がない。
- 異常系不足:
  - COM01009、COM01010、COM01011、IFC06001、IFC06004、削除未選択、候補外 columnId、通信失敗の各ケースが未検証である。

## 総評
- High 指摘は、削除操作の前提制御崩れと、優先度判定条件の候補再構築未達であり、いずれも画面の基本操作と保存整合性に直接影響する。
- Middle 指摘では、編集モードの変更禁止制御、自身除外候補、対象なし時の復帰導線に設計差分が残っている。
- テスト未整備の影響が大きく、分岐の多い画面に対して回帰検知手段が不足しているため、実装修正と同時に画面単体テストの整備が必要である。

## 残留リスク・確認できなかった範囲
- フロントエンドから AuthContext などの権限制御を直接利用している形跡は確認できず、ルートガードやバックエンド権限チェックとの責務分担は未確認である。
- バックエンド API が一部の不整合を吸収している可能性はあるが、本レビューはフロントエンド実装の設計適合性を中心に判定している。
