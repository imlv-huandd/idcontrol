# 連携先インターフェイス編集 レビュー結果

## 指摘事項

### 1. 更新処理の権限チェックが直接更新経路で確認されていない
- 優先度: High
- 種別: 観点不足
- 対象: 単体テスト仕様書‗連携先インターフェイス編集.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md](spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md) の「バリデーション定義」で、権限チェックはサーバーサイドで実施し、ログインユーザーがテナント管理者権限または対象システムの編集権限を持つことが必須と定義されている。
  - 実装: [単体テスト仕様書‗連携先インターフェイス編集.csv](単体テスト/単体テスト仕様書‗連携先インターフェイス編集.csv) の権限チェックは直接URLアクセスの拒否確認に限定されており、更新ボタン押下時に権限不足なら更新処理が中断されること、また COM01001 相当のエラーで DB 更新が発生しないことを確認するケースがない。
- 指摘内容:
  - 画面参照の拒否だけでは、更新送信時のサーバー側認可漏れを検出できない。
  - 認可不備が残ると、画面表示は拒否されても更新 API 相当の経路から不正更新できるリスクを見逃すため、セキュリティ観点として重要である。
- 期待されるテスト:
  - 権限なしユーザーで更新ボタン押下時に COM01001 相当の権限エラーとなること。
  - 権限なしでは DB 更新・履歴更新・操作ログ記録が発生しないこと。
  - 権限ありユーザーでは更新が正常終了すること。

### 2. 変更モードの初期表示で対象データなしの異常系が不足している
- 優先度: Middle
- 種別: 項目不足
- 対象: 単体テスト仕様書‗連携先インターフェイス編集.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md](spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md) の「初期表示（変更モード）」では、パラメータのシステムID・インターフェイスIDに該当データが存在しない場合に COM01009 を表示し、連携システム／インターフェイス一覧へ遷移すると定義されている。
  - 実装: [単体テスト仕様書‗連携先インターフェイス編集.csv](単体テスト/単体テスト仕様書‗連携先インターフェイス編集.csv) の画面初期表示は正常系のみで、存在しないシステムID／インターフェイスID、または取得0件時のエラー遷移を確認する項目がない。
- 指摘内容:
  - 編集画面の代表的な異常系である「対象データなし」を確認できず、初期表示のエラーハンドリングが未検証になっている。
  - 0件時のメッセージと一覧遷移が確認できないため、仕様確認に使うには不足している。
- 期待されるテスト:
  - 存在しないシステムID／インターフェイスIDで画面を開いた場合に COM01009 が表示されること。
  - 一覧へ遷移し、画面項目が表示されないこと。

### 3. 登録モードと登録処理の観点が抜けている
- 優先度: Middle
- 種別: 項目不足
- 対象: 単体テスト仕様書‗連携先インターフェイス編集.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md](spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md) には、追加モードの初期表示、登録ボタン押下、連携先インターフェイス／連携先インターフェイス項目／統合定義の新規登録、操作ログ記録、登録完了後の一覧遷移が定義されている。
  - 実装: [単体テスト仕様書‗連携先インターフェイス編集.csv](単体テスト/単体テスト仕様書‗連携先インターフェイス編集.csv) は更新ボタン押下のケースしかなく、登録ボタン押下、追加モードの初期値、登録時の必須チェック、登録データのDB反映、操作ログまでを確認する項目がない。
- 指摘内容:
  - この項目表では編集画面の一部しか確認できず、仕様上の登録機能が未網羅である。
  - 追加モードの表示分岐や、登録時にのみ発生する項目追加・削除・D&D・登録後遷移の確認が欠落している。
- 期待されるテスト:
  - 追加モードの初期表示でデフォルト値と表示／非表示状態を確認すること。
  - 登録ボタン押下時の正常系、必須入力エラー、確認ダイアログキャンセル、DB登録結果、操作ログ、完了メッセージを確認すること。

### 4. 更新時の入力チェックが必須未入力以外に広がっていない
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗連携先インターフェイス編集.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md](spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md) の「バリデーション定義」には、インターフェイス名100文字、ファイル名300文字、チェック起動時刻0～23、基準日オフセット-99～99、重複名禁止、優先度判定条件の件数／項目／優先順、統合定義の1件以上選択と自身除外など、多数の分岐・境界値が定義されている。
  - 実装: [単体テスト仕様書‗連携先インターフェイス編集.csv](単体テスト/単体テスト仕様書‗連携先インターフェイス編集.csv) の更新ボタン押下は、必須未入力、楽観排他エラー、正常更新のみで、境界値・不正値・重複・優先度条件・統合対象・変更有無チェックを個別に検証する項目がない。
- 指摘内容:
  - 1ケースに複数の判定責務が混在している一方、仕様上の主要な入力検証が抜けているため、原因切り分けできる粒度になっていない。
  - 更新で誤データを防ぐために必要な境界値、列挙値、重複、件数チェックが未確認である。
- 期待されるテスト:
  - 種別設定の各項目について、必須・文字数・列挙値・数値範囲の異常系を個別に確認すること。
  - 入力項目／出力項目名の重複、優先度判定条件の件数不足、項目未選択、優先順の空要素混入、統合対象の未選択・自身選択をそれぞれ確認すること。
  - 更新前後差分なしで COM01011 になることを確認すること。

### 5. 表示切替と戻る操作の状態分岐が不足している
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗連携先インターフェイス編集.csv
- 根拠:
  - 設計書: [spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md](spec/基本設計/機能設計/090.連携システム/連携先/連携先インターフェイス編集.md) のイベント定義には、インターフェイス種別変更、連携タイミング種別変更、定義種別変更、出力種別変更、戻るボタン押下があり、連携しない時の全非活性化、統合時の入力／出力エリア切替、変更あり時の COM01008 確認が定義されている。
  - 実装: [単体テスト仕様書‗連携先インターフェイス編集.csv](単体テスト/単体テスト仕様書‗連携先インターフェイス編集.csv) は項目マッピング／連携指示／戻るの遷移確認のみで、種別変更による表示・活性状態の切替、統合定義の表示、出力種別による優先度条件表示、変更あり戻る時の確認ダイアログを確認するケースがない。
- 指摘内容:
  - 画面の主要な状態遷移が未確認で、条件付き表示や非活性制御の不具合を検出できない。
  - 戻るボタンについても未変更時しか確認しておらず、編集途中の破棄確認が抜けている。
- 期待されるテスト:
  - インターフェイス種別を変更したときの表示項目・非活性状態を確認すること。
  - 連携タイミング種別変更で日数系／前段インターフェイスの表示切替を確認すること。
  - 定義種別を通常／統合に切り替えた際の各エリアの表示・非表示を確認すること。
  - 出力種別を優先度系にしたときの優先度判定条件表示を確認すること。
  - 変更あり状態で戻る押下時に COM01008 の確認ダイアログが出ることを確認すること。

## 総評
更新系の正常／異常系が最小限に留まっており、登録モード、初期表示の0件異常、権限のサーバー側検証、条件分岐を伴う入力チェックが不足しています。
特に権限チェックと更新系バリデーションは、誤更新や認可不備を見逃すと影響が大きいため、優先して補強が必要です。
画面の状態遷移と戻る確認も未検証で、設計書の主要分岐を単体テスト項目表で追えていません。

## 残留リスク・確認できなかった範囲
- 仕様書上の各入力項目の詳細な文字種制約や、実装の実際のメッセージ出し分けは、提示された項目表だけでは確認できませんでした。
- 追加モードの実装有無は設計書上は定義されていますが、今回の対象項目表には含まれていないため、実際のテスト計画上のスコープは別途確認が必要です。
