# コード変換グループ検索 レビュー結果

## 指摘事項

### 1. ページング時に検索ページが常に1ページ目へ戻る実装不備
- 優先度: High
- 種別: 実装不備
- 対象: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx)
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md) の検索ボタン押下・ページング仕様では、選択ページで再検索されることが前提。
  - 実装: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx) で Pagination から handleSearch に page が渡る構造に対し、loadConversionGroups の引数順が conditions, page になっているため、ページ遷移時に page が条件側へ入り、検索実行が1ページ目固定になり得る。
- 指摘内容:
  - ページネーション操作時に意図したページで検索されず、ユーザーが2ページ目以降を閲覧できない挙動となるリスクがある。
- 期待されるテスト:
  - 2ページ目、最終ページ、中間ページを選択した際に、APIへ送信される page が選択値になること。
  - ページング後に一覧表示とページ表示が一致すること。

### 2. 削除後再検索で検索条件パラメータが破損する実装不備
- 優先度: High
- 種別: 実装不備
- 対象: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx)
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md) の削除ボタン押下仕様では、削除後に現在ページで再検索し、データなし時は最終ページ表示が必要。
  - 実装: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx) で searchConversionGroups 呼び出し時に codeConversionGroupName 文字列を conditions として渡しており、URLSearchParams 生成時に想定キー codeConversionGroupName が崩れる可能性がある。
- 指摘内容:
  - 削除後の再検索で検索条件が正しく適用されず、削除前と異なる結果表示や検索条件消失が発生するリスクがある。
- 期待されるテスト:
  - 検索条件入力後に削除した場合でも、同一条件で再検索されること。
  - 最終件削除時に1ページ戻り動作を含め、期待件数とページが一致すること。

### 3. 新規登録ボタンの権限制御未実装
- 優先度: High
- 種別: 実装不備
- 対象: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx)
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md) の項目定義で、新規登録ボタンはテナント管理者のみ表示と明記。
  - 実装: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx) では権限判定なしで新規登録ボタンを常時表示している。
- 指摘内容:
  - 権限外ユーザーにも新規登録導線が露出し、設計逸脱かつ認可不備の温床となる。
- 期待されるテスト:
  - テナント管理者は表示、連携システム管理者・一般ユーザーは非表示になること。
  - 権限変更時に表示状態が正しく追随すること。

### 4. 検索失敗時のエラーが画面に表示されない
- 優先度: Middle
- 種別: 実装不備
- 対象: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx)
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md) では異常時にメッセージ表示して処理を中断する運用を前提。
  - 実装: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx) では search 失敗時に error state を設定するが、描画側で error を表示していない。
- 指摘内容:
  - 通信失敗時にユーザーが失敗原因を認識できず、再試行判断が困難。
- 期待されるテスト:
  - 検索APIが 4xx/5xx の場合にエラーメッセージが表示されること。
  - エラー表示後の再検索で正常表示に戻ること。

### 5. 設計で要求されるソート順の担保責務が不明確
- 優先度: Middle
- 種別: 設計確認事項
- 対象: コード変換グループ検索機能
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ検索.md) でコード変換グループ名昇順が指定されている。
  - 実装: [frontend/src/pages/codes/CodeConversionGroupSearch.jsx](frontend/src/pages/codes/CodeConversionGroupSearch.jsx) ではソート処理を持たず、API応答順をそのまま表示している。
- 指摘内容:
  - 昇順保証がバックエンド責務である前提だが、責務分界が明文化されていない場合は仕様逸脱検知が困難。
- 期待されるテスト:
  - API応答が昇順であることをE2EまたはAPIテストで確認すること。
  - 画面側では受信順表示であることを明示し、責務を固定すること。

### 6. フロントエンド単体テスト未整備により仕様検証が未実施
- 優先度: Middle
- 種別: テスト不足
- 対象: コード変換グループ検索機能
- 根拠:
  - 設計書: [spec/050.テスト/テスト観点.md](spec/050.テスト/テスト観点.md) の単体テスト観点で、正常系・入力値バリエーション・境界値・分岐条件・データ入出力・非更新確認・異常系を網羅する方針。
  - 実装: フロントエンド配下に対象機能のテストコードが存在しないため、画面仕様の担保ができていない。
- 指摘内容:
  - 現状は回帰時に設計逸脱を検知できず、ページング・権限表示・削除フロー・エラー表示の破壊的変更を見逃すリスクが高い。
- 期待されるテスト:
  - 正常系: 初期表示、検索、編集遷移、新規登録遷移、削除成功。
  - 入力値バリエーション: 未入力検索、部分一致検索、該当なし検索。
  - 境界値: 0件、1件、20件、21件、最終ページ境界。
  - 分岐条件: 削除キャンセル、権限別表示、ページング活性非活性。
  - データ入出力: 先頭5件表示と ...（X件）表記、表示件数ラベル。
  - 非更新確認: 削除キャンセル時に一覧不変。
  - 異常系: 検索失敗、削除失敗、権限不足、タイムスタンプ不一致。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足:
  - 初期表示、検索成功、編集遷移、新規登録遷移、削除成功、削除後再検索の自動検証が未実装。
- 入力値バリエーション不足:
  - コード変換グループ名の未入力、部分一致、該当なしの比較検証が未実装。
- 境界値不足:
  - 0件、1件、20件、21件、最終ページでの挙動確認が未実装。
- 分岐条件不足:
  - 削除キャンセル分岐、権限別UI分岐、新規登録ボタン表示分岐、ページボタン活性制御分岐が未実装。
- データ入出力不足:
  - 先頭5件表示ロジック、超過時 ...（X件）表記、削除後件数更新の検証が未実装。
- 非更新確認不足:
  - キャンセル時にデータが不変であることの検証が未実装。
- 異常系不足:
  - 検索API失敗、削除API失敗、権限不足、楽観ロック不一致時の表示検証が未実装。

## 総評
- High指摘として、ページング処理と削除後再検索条件の不整合、ならびに新規登録ボタンの権限制御未実装を確認した。
- いずれも通常操作で再現し得るため、画面機能不全と認可観点の品質リスクが高い。
- 修正優先順位は、ページング不整合と削除後再検索不整合を最優先、その次に権限制御表示、最後にエラー表示と責務明確化。

## 残留リスク・確認できなかった範囲
- バックエンド実装側での最終的な権限チェック、ソート保証、楽観ロック時メッセージIDの最終仕様は本レビュー範囲外のため、画面単体では完全保証できない。
- APIの実レスポンススキーマ差異がある場合、画面表示やエラー文言の整合性に追加リスクが残る。
