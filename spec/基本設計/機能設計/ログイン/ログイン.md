## 機能概要

当システムへのログイン機能を提供する。
ActiveDirectory（Azure AD）のSAML認証を利用したシングルサインオン（SSO）機能を前提として、画面でのログインは実装しない。

### 処理フロー

- ユーザーが本システムの任意のURL（例: https://{テナントコード}.example.com）にアクセス
- サブドメインからテナントコード部を抽出
- テナントコードでテナントマスタを検索し、テナント設定を取得する
  - 使用可能ログイン方法を判定する。
    - テナント設定の`useADSAMLSSO`の設定が"ON"の場合
      - テナントの各Identity Providerの設定（各項目はエンティティ定義を参照）を取得
      - 取得した設定を元にIdPに認証行う
      - 認証成功後、メールアドレスを元に対象テナントのユーザーマスターを検索する
- ユーザーが見つかった場合、ログイン成功としてアクセス元URLにリダイレクトする。
- 見つからない場合、ログイン失敗として認証エラーページにリダイレクトする。


**Note:** 認証済みユーザーがアクセスした場合は直接リクエストされたページが表示される。



## ActiveDirectory SAML認証

**テナントごとに異なるEntra Idテナントと連携**を可能とする。  
そのため、SAML IdP設定はテナントマスターに保持し、ログイン時に動的に適切な設定を取得する。

### テナントマスターの保持項目

詳細はエンティティ定義の**テナント設定 設定項目**を参照。

### エンドポイント定義

Saml認証を行うための各種エンドポイントは下記の通り。

#### 本システム（SP）側エンドポイント

| エンドポイント                   | URL                   | 用途                                                                                                  | HTTPメソッド |
| :------------------------------- | :-------------------- | :---------------------------------------------------------------------------------------------------- | :----------- |
| 認証開始（内部）                 | `/auth/saml/login`    | 認証ミドルウェアから呼ばれるSAML認証フロー開始エンドポイント<br>※ユーザーが直接アクセスすることはない | GET          |
| ACS (Assertion Consumer Service) | `/auth/saml/callback` | IdPからのSAMLレスポンスを受信し、セッション確立後に元のURLへリダイレクト                              | POST         |
| メタデータ                       | `/auth/saml/metadata` | SPのSAMLメタデータを提供（Azure AD設定時に使用）                                                      | GET          |
| ログアウト                       | `/auth/saml/logout`   | SSOログアウトを実行                                                                                   | GET/POST     |
| SLO (Single Logout)              | `/auth/saml/slo`      | IdPからのログアウト要求を受信                                                                         | POST         |

### IdP（Entra ID）側エンドポイント

詳細はエンティティ定義の**テナント設定 設定項目**を参照。
