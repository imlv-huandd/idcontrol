# コード変換グループ編集 レビュー結果

## 指摘事項

### 1. 更新権限チェックの分岐網羅が不足している
- 優先度: High
- 種別: 観点不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) の更新ボタン押下およびバリデーション定義 No.7（権限チェックはテナント管理者許可、変更前管理連携システム管理者許可、変更前管理連携システム null 許可の分岐を持つ）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) の No.17, No.19, No.20 は「権限なし」系のみで、許可側分岐の確認がない
- 指摘内容:
  - 権限制御はセキュリティ要件であり、拒否系のみでは不十分。許可されるべきロール・状態で更新可能であること、変更前管理連携システムが null の場合の許可挙動が未確認。
- 期待されるテスト:
  - テナント管理者で更新可能
  - 変更前管理連携システムの連携システム管理者で更新可能
  - 変更前管理連携システムが null の対象を連携システム管理者で更新可能
  - 許可時に COM01001 が出ないこと（非発生確認）

### 2. 更新時のトランザクション失敗時ロールバック検証が不足している
- 優先度: High
- 種別: 項目不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) の更新ボタン押下（コード変換マスター登録で1件でも失敗した場合は全件ロールバックし COM01010 を表示）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) の No.6 は楽観排他のみで、途中登録失敗のロールバック確認がない
- 指摘内容:
  - 途中失敗時の全体ロールバックが未確認のため、誤更新・部分更新が見逃されるリスクがある。
- 期待されるテスト:
  - 更新時にコード変換マスター登録の一部を失敗させ、COM01010 を表示
  - コード変換グループマスターおよびコード変換マスターが更新前状態のままであること（非更新確認）
  - 更新対象外データにも副作用がないこと

### 3. 編集モード初期表示の対象データなし異常が未検証
- 優先度: High
- 種別: 項目不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) の画面初期表示（編集モード）（対象グループ不存在時は COM01009 表示してダイアログを閉じる）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) の No.2 は正常表示のみ
- 指摘内容:
  - ID 指定起動時の主要異常分岐が欠落しており、データ欠損時の利用者向け挙動を確認できない。
- 期待されるテスト:
  - 存在しないコード変換グループ ID で起動し COM01009 を表示
  - 画面継続編集できないこと（ダイアログクローズ後の状態を確認）

### 4. キャンセル操作の変更有無分岐が不足している
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) のキャンセルボタン押下（変更あり時 COM01008 確認ダイアログ、キャンセル時は画面遷移しない）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) の No.7 は「変更なしで戻る」しかなく、変更あり分岐がない
- 指摘内容:
  - 変更破棄確認の分岐が未確認で、誤遷移や誤破棄を見逃す。
- 期待されるテスト:
  - 入力変更ありでキャンセル押下時に COM01008 表示
  - ダイアログでキャンセル選択時は同画面に残る
  - ダイアログで OK 選択時のみ検索画面へ遷移

### 5. 行追加・行削除・行移動イベントのテストが欠落している
- 優先度: Middle
- 種別: 項目不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) のイベント定義 No.3, No.4, No.5 とイベント詳細（削除確認 COM01007、No.再採番、削除キャンセル、行移動後再採番）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) に該当イベント項目がない
- 指摘内容:
  - 画面主要機能の操作系イベントが未検証で、仕様網羅性不足。
- 期待されるテスト:
  - 追加押下で末尾に空行追加
  - 削除押下で COM01007 表示、キャンセル時は行が残る
  - 削除確定時は画面上のみ削除され No. が 1 から再採番
  - 1 行時は削除ボタン非活性
  - 行移動時に表示順 No. が再採番

### 6. 登録・更新の確認ダイアログキャンセル分岐が不足している
- 優先度: Middle
- 種別: 観点不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) の登録ボタン押下・更新ボタン押下（COM01006 でキャンセル時は処理終了）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) の No.3, No.5 は OK 押下のみ
- 指摘内容:
  - ユーザー操作分岐の重要経路（キャンセル）未確認で、誤更新リスクが残る。
- 期待されるテスト:
  - COM01006 表示確認
  - キャンセル選択時に DB 更新されないこと
  - 画面遷移しないこと

### 7. 初期表示仕様の詳細観測が不足し、期待結果が曖昧なケースがある
- 優先度: Low
- 種別: 記載不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md](spec/基本設計/機能設計/100.コード定義/コード変換グループ編集.md) の新規初期表示詳細（コード変換エリア空行1件、タイトル表示切替、登録/更新ボタン表示切替）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) の No.1, No.18 は期待結果が抽象的で観測項目不足
- 指摘内容:
  - 「正常に処理されること」だけでは合否判定が実施者依存となり、単体テスト記載内容・評価基準を満たしにくい。
- 期待されるテスト:
  - 新規初期表示で空行1件、更新ボタン非表示、登録ボタン表示、編集タイトル非表示を明示
  - 境界値 No.18 は登録/更新後の画面遷移、完了メッセージ ID、DB 登録値（100文字保存）まで具体化

### 8. 非更新確認と副作用確認の観点が不足している
- 優先度: Low
- 種別: 観点不足
- 対象: 単体テスト仕様書‗コード変換グループ編集
- 根拠:
  - 設計書: [spec/050.テスト/テスト観点.md](spec/050.テスト/テスト観点.md) の単体テスト観点（非更新確認）と単体テスト作成方針（更新対象外データが更新されないことを確認）
  - 実装: [単体テスト/単体テスト仕様書‗コード変換グループ編集.csv](単体テスト/単体テスト仕様書‗コード変換グループ編集.csv) は主に成功/エラー表示中心で、対象外データ不変の確認記載が少ない
- 指摘内容:
  - エラー時の「更新されないこと」「対象外不変」の明記が不足し、副作用検知力が弱い。
- 期待されるテスト:
  - バリデーションエラー時に DB 非更新
  - 重複エラー時に対象・対象外とも非更新
  - 楽観排他エラー時に更新対象外データ不変

## 総評
- High 指摘は、権限制御分岐、更新ロールバック、編集対象なし異常の未網羅であり、障害・不整合・アクセス制御不備の見逃しに直結する。
- まず High を優先してケース追加し、次に操作分岐（追加/削除/移動/キャンセル）を補完することで、設計書網羅率と再現性が大きく向上する。
- 併せて期待結果をメッセージ ID、遷移有無、DB 差分まで具体化し、実施者依存を排除する必要がある。

## 残留リスク・確認できなかった範囲
- 実装コード（frontend/functions/shared/tests）への直接照合は未実施。今回は設計書と単体テスト項目表の突合に基づくレビューであり、実装分岐との完全一致は別途コード照合が必要。
