# コードグループ編集 レビュー結果

## 指摘事項

### 1. ドラッグ&ドロップ時に未ドラッグ状態の drop で不正データ化する可能性
- 優先度: High
- 種別: 実装不備
- 対象: frontend/src/pages/codes/CodeGroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/100.コード定義/コードグループ編集.md（「コード行移動」: ドラッグ行をドロップ位置に移動し、No.を再設定）
  - 実装: handleDrop で dragIndex の null/範囲外ガードがなく、newCodes[dragIndex] 取得後に splice 実行している
- 指摘内容:
  - dragIndex が未設定（null）や不正値でも処理継続するため、先頭行削除や undefined 挿入が起こり得る。結果として描画崩れ・バリデーション時例外（row.codeName 参照）につながる。
- 期待されるテスト:
  - ドラッグ開始なしで drop が発生した場合に状態が不変であること
  - dragIndex が同一行/範囲外/null の場合に codes と rowErrors が破壊されないこと

### 2. 削除ボタンの非活性条件が設計逸脱（1行時に削除可能）
- 優先度: Middle
- 種別: 実装不備
- 対象: frontend/src/pages/codes/CodeGroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/100.コード定義/コードグループ編集.md（項目定義 No.10: 「コードエリアの行が1行しかない場合、非活性」）
  - 実装: 削除ボタンの disabled 条件が loading のみで、codes.length === 1 を考慮していない
- 指摘内容:
  - 1行時でも削除でき、画面上で0件状態を作れてしまう。登録/更新時に COD02004 でブロックはされるが、UI仕様と不一致。
- 期待されるテスト:
  - 1行時は削除ボタンが disabled であること
  - 2行以上では削除可能で、削除後に No.(表示順) が連番再採番されること

### 3. 画面表示文言が設計と不一致（基本情報エリア見出し欠落、コードエリア見出し差異）
- 優先度: Low
- 種別: 実装不備
- 対象: frontend/src/pages/codes/CodeGroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/100.コード定義/コードグループ編集.md（基本情報エリアタイトル: 「基本情報」、コードエリアタイトル: 「コード」）
  - 実装: 基本情報エリアタイトルが未表示、コードエリア見出しが「コード一覧」
- 指摘内容:
  - 動作影響は軽微だが、設計トレーサビリティと画面統一性の観点で差異がある。
- 期待されるテスト:
  - 画面初期表示時に見出し文言が設計値と一致すること（スナップショット/DOMアサーション）

### 4. 行追加時の viewIndex 採番がクロージャ参照で不安定
- 優先度: Low
- 種別: 実装不備
- 対象: frontend/src/pages/codes/CodeGroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/100.コード定義/コードグループ編集.md（追加時は末尾追加、No.は1からの連番）
  - 実装: addCode 内で setCodes(prev => [...prev, {..., viewIndex: codes.length + 1}]) と外側の codes を参照
- 指摘内容:
  - 連続操作時に stale state で viewIndex が期待とずれる余地がある。現状は再採番処理で吸収される場面が多いが、採番処理としては脆弱。
- 期待されるテスト:
  - 追加ボタン連打時でも viewIndex が欠番/重複なく連番になること

### 5. フロントエンド単体テストが未作成で、仕様観点の回帰保証がない
- 優先度: Middle
- 種別: テスト不足
- 対象: コードグループ編集機能（frontend）
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md（単体テスト観点: 正常系/入力値バリエーション/境界値/分岐条件/データ入出力/非更新確認/異常系）
  - 実装: frontend 側に CodeGroupEdit を対象としたテストコードが存在しない（バックエンド tests/functions/codegroups/test_codegroups.py は存在）
- 指摘内容:
  - 画面機能の主要分岐（新規/編集、権限別選択肢、削除確認、D&D再採番、API失敗時表示）が自動検証されず、将来改修で仕様逸脱を検知しづらい。
- 期待されるテスト:
  - 正常系: 新規登録成功、更新成功、キャンセル遷移
  - 入力値バリエーション: 必須未入力、管理連携システム未設定/設定、権限別選択候補
  - 境界値: 100文字ちょうど/101文字、コード0件
  - 分岐条件: isEditMode の表示差分、削除確認キャンセル、hasChanged 有無でのキャンセル挙動
  - データ入出力: API リクエスト body/query の内容（times, viewIndex, codeId 等）
  - 非更新確認: バリデーションエラー時に API 未実行
  - 異常系: getCodeGroup 失敗時 COM01009 ダイアログ、create/update 失敗時エラー表示

### 6. 設計確認事項: 管理連携システム候補の取得失敗時の画面継続可否の扱い
- 優先度: Low
- 種別: 設計確認事項
- 対象: frontend/src/pages/codes/CodeGroupEdit.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/100.コード定義/コードグループ編集.md（初期表示で候補制御の要件はあるが、候補取得失敗時の画面可否は明記なし）
  - 実装: loadDataSelect 失敗時は alert 表示のみで画面操作継続
- 指摘内容:
  - 権限ベース候補が取得できない状態で登録/更新可能とするかは運用上の判断が必要。仕様未定義のため確認事項として分離。
- 期待されるテスト:
  - 候補取得 API 失敗時の画面状態（入力可否、登録/更新可否、メッセージ）を仕様に応じて検証

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足:
  - 新規登録成功、更新成功、削除確認後の行削除と再採番、キャンセル遷移
- 入力値バリエーション不足:
  - コードグループ名未入力、コード名/コード値未入力、管理連携システム未設定/設定、権限別選択肢
- 境界値不足:
  - 100文字上限の直前/ちょうど/超過、コード件数0件/1件/複数件
- 分岐条件不足:
  - 新規モード/編集モード表示分岐、hasChanged 有無、削除確認 OK/Cancel、D&Dでの並び替え分岐
- データ入出力不足:
  - create/update の request body（adminSystemId null 化、times、viewIndex 連番）と API 失敗時レスポンス反映
- 非更新確認不足:
  - バリデーションエラー時・確認ダイアログキャンセル時に API が呼ばれないこと
- 異常系不足:
  - 初期取得失敗（COM01009）、更新競合/失敗（COM01010）、権限関連 API 失敗時の表示

## 総評
- 重大度が最も高いのは、ドラッグ&ドロップ処理の入力防御不足で、行データ破壊につながる点です。
- 次に、削除ボタン非活性条件の設計逸脱があり、UI仕様との不整合が残っています。
- フロントエンドの自動テスト未整備により、仕様回帰の検知能力が不足しています。
- 修正優先順位は D&D防御 > 削除活性条件 > テスト整備 の順が妥当です。

## 残留リスク・確認できなかった範囲
- spec/詳細設計 配下で本機能に対応する詳細処理仕様の明示資料は確認できず、エラー時の画面継続可否など一部は設計確認事項として扱った。
- バックエンド実装の妥当性（権限/重複/ロールバック詳細）は本レビューの主対象外のため、画面連携観点に限定して評価した。
