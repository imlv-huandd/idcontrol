# 操作ログ レビュー結果

## 指摘事項

### 1. ページング時に検索条件が失われ、2ページ目以降が仕様通りに検索できない
- 優先度: High
- 種別: 実装不備
- 対象: AuditLogSearch.jsx
- 根拠:
  - 設計書: spec/基本設計/機能設計/120.管理機能/操作ログ.md の「検索ボタン押下」「検索結果エリア」。検索条件に一致する結果をページネーションで継続表示する前提で、現在ページは1ページ目に設定し、その後はページング共通仕様に従う。
  - 実装: frontend/src/pages/admin/AuditLogSearch.jsx では Pagination に handleSearch={loadAuditLogs} を渡している一方、frontend/src/components/Pagination.jsx はページ押下時に handleSearch(null, page) を呼ぶ契約になっている。その結果、loadAuditLogs(null, 2) が実行され、conditions に null が入り、元の検索条件を保持できない。
- 指摘内容:
  - 初回検索後に2ページ目以降へ遷移すると、検索条件を維持したまま再検索する仕様を満たせていません。
  - 実装契約が UserSearch 系画面のパターンとも一致しておらず、ページ遷移時に条件なし検索または意図しない検索が発生します。
  - 通常操作で再現し、検索結果の正しさを直接損なうため、リリース前修正が必要です。
- 期待されるテスト:
  - 条件指定で検索後、2ページ目へ遷移しても同一条件のまま page=2 で API が呼ばれること。
  - 先頭・前・次・最終ボタンそれぞれで条件保持とページ番号更新が正しいこと。
  - 0件、20件、21件、複数ページでページング表示と検索条件保持が成立すること。

### 2. 操作ログ画面の権限制御がフロントエンドに実装されておらず、設計上の利用制限を満たしていない
- 優先度: High
- 種別: 実装不備
- 対象: 操作ログ画面 / 画面ルーティング / メニュー表示
- 根拠:
  - 設計書: spec/基本設計/概要資料/権限について では管理機能「操作ログ」に利用権限の定義がある。spec/基本設計/概要資料/外部設計/ユーザーの権限について でも、操作ログを利用可能な権限が限定されている。
  - 実装: frontend/src/App.jsx で /audit-logs ルートが保護されておらず、frontend/src/components/Layout.jsx でもメニュー表示条件がない。frontend/src/pages/admin/AuditLogSearch.jsx でも frontend/src/common/UserAuthority.jsx を用いた権限判定がなく、frontend/src/auth/ProtectedRoute.jsx も該当ルートで未使用。
- 指摘内容:
  - 設計では操作ログの利用者が限定されているにもかかわらず、フロントエンドではメニュー表示、直接 URL アクセス、画面描画のいずれでも権限制御がありません。
  - 認可要件に対する実装漏れであり、サーバー側で拒否できる前提があっても、画面露出と操作導線の観点で仕様未達です。
  - 認可はセキュリティ要件に該当するため、高優先度での是正が必要です。
- 期待されるテスト:
  - 権限ありユーザーのみメニュー表示されること。
  - 権限なしユーザーが /audit-logs に直接アクセスした際に画面表示されないこと。
  - 権限取得失敗時に安全側で非表示または遷移拒否となること。

### 3. 権限仕様の設計書間で対象ロールの定義が一致しておらず、実装判断基準が曖昧
- 優先度: Middle
- 種別: 設計確認事項
- 対象: 操作ログ機能の権限仕様
- 根拠:
  - 設計書: spec/基本設計/概要資料/権限について では操作ログの利用者が「テナント管理者のみ」と読める一方、spec/基本設計/概要資料/外部設計/ユーザーの権限について では「テナント管理者、連携システム管理者、マスターデータ管理者」が利用可能と読める。
  - 実装: frontend/src/common/UserAuthority.jsx には複数ロールの判定関数が存在するが、AuditLogSearch.jsx ではいずれの権限も参照していないため、どのロールを許可すべきか実装に反映されていない。
- 指摘内容:
  - 権限仕様の一次情報が一致しておらず、実装すべき認可条件を確定できません。
  - この状態で修正を進めると、過剰制限または制限不足のいずれかを招くため、設計の正本を明確化する必要があります。
- 期待されるテスト:
  - 確定した許可ロールごとに、メニュー表示、画面遷移、検索実行可否を検証すること。
  - 不許可ロールでは同一観点がすべて拒否されること。

### 4. 操作日時条件の仕様と実装が一致しているか判断できず、日単位検索要件が未確定のままになっている
- 優先度: Middle
- 種別: 設計確認事項
- 対象: 操作日時検索条件
- 根拠:
  - 設計書: spec/基本設計/機能設計/120.管理機能/操作ログ.md の項目定義では「YYYY/MM/DD HH:MM 形式の日時入力」とある一方、イベント詳細では「操作日時（From）00:00:00 <= 操作日時 <= 操作日時（To）23:59:59」と記載されており、日単位に丸める仕様にも読める。
  - 実装: frontend/src/pages/admin/AuditLogSearch.jsx は type="datetime-local" で時刻まで入力させ、functions/auditlogs/searchAuditLogs/app.py および shared/repositories/operationLogRepository.py は受け取った ISO 文字列をそのまま範囲条件に使っている。
- 指摘内容:
  - 現実装は「入力した日時の完全一致範囲」で検索しますが、設計文言どおりに日単位へ補正する仕様なら未達です。
  - 設計書内に解釈差分があるため、仕様を確定しないと検索結果の妥当性をレビュー完了とできません。
- 期待されるテスト:
  - 仕様確定後、From のみ指定、To のみ指定、同日指定、時刻付き指定で期待範囲に一致すること。
  - 日単位仕様なら 00:00:00 / 23:59:59 へ補正されること。

### 5. フロントエンド単体テストが未作成で、spec/050.テスト/テスト観点.md に対する必須観点を網羅できていない
- 優先度: Middle
- 種別: テスト不足
- 対象: 操作ログフロントエンド全体
- 根拠:
  - 設計書: spec/050.テスト/テスト観点.md では、正常系、入力値バリエーション、境界値、分岐条件、データ入出力、非更新確認、異常系の観点で単体テストを求めている。spec/基本設計/機能設計/120.管理機能/操作ログ.md では、日時範囲チェック、0件時メッセージ、30文字超過時の詳細ボタン、詳細ダイアログ、ページネーションが仕様化されている。
  - 実装: frontend/src/pages/admin/AuditLogSearch.jsx に対応するフロントエンドテストコードは未発見であり、関連する frontend/src/components/Pagination.jsx、frontend/src/components/AlertMessage.jsx、frontend/src/components/LoadingModal.jsx を含めた UI 振る舞いの検証が存在しない。
- 指摘内容:
  - 現状のままでは、主要分岐と境界値を機械的に担保できず、実際に今回のページング不具合のような欠陥を検出できません。
  - 特に、仕様依存の UI 分岐と異常系は目視確認頼みになっており、回帰リスクが高い状態です。
- 期待されるテスト:
  - 正常系: 条件指定検索成功、0件メッセージ表示、詳細ダイアログ表示/閉じる、検索後の currentPage=1 初期化。
  - 入力値バリエーション不足: 操作ユーザー名部分一致、かな部分一致、対象機能「すべて」/個別選択、From のみ、To のみ、両方指定。
  - 境界値不足: 操作内容 30文字ちょうど/31文字、結果件数 0/20/21、最初/最後のページ。
  - 分岐条件不足: 日時範囲エラー時に COM02018 を表示して検索中断すること、長文時のみ詳細ボタン表示すること、クリアで結果エリア非表示になること。
  - データ入出力不足: 操作日時降順表示、API エラー時の AlertMessage 表示、改行を含む操作内容がダイアログで保持されること。
  - 異常系不足: fetch 失敗、401/403/500 応答、想定外レスポンス時の画面挙動。

## テスト不足の整理（spec/050.テスト/テスト観点.md 準拠）
- 正常系不足: 条件指定検索成功、検索結果表示、0件時メッセージ、詳細ダイアログ表示・閉じる、検索後の1ページ目初期化。
- 入力値バリエーション不足: 操作ユーザー名部分一致、操作ユーザー名かな部分一致、対象機能「すべて」/個別機能、Fromのみ、Toのみ、両方指定。
- 境界値不足: 操作内容30文字/31文字、件数0/20/21、最終ページ、複数ページ遷移。
- 分岐条件不足: 日時範囲エラー、詳細ボタン表示有無、ページ遷移時の条件保持、クリア後の検索結果エリア非表示。
- データ入出力不足: 操作日時降順、ページング件数表示、改行付き操作内容の詳細表示、エラーメッセージ表示。
- 非更新確認不足: 検索のみで入力値が意図せず変化しないこと、エラー時に不正な状態遷移を起こさないこと。
- 異常系不足: 通信失敗、401/403/500、想定外レスポンス、不正な日時形式の応答時の画面挙動。

## 総評
- High 指摘は、ページング不具合と権限制御未実装の2点です。どちらも通常操作または認可要件に直結し、リリース前修正が必要です。
- そのうえで、権限仕様と操作日時仕様に設計書間の解釈差分が残っており、修正方針の確定には設計の正本整理が必要です。
- フロントエンドテストが未整備のため、修正時は仕様ベースの単体テスト追加を同時に行うべきです。

## 残留リスク・確認できなかった範囲
- spec/詳細設計 配下に操作ログの詳細設計書は未発見であり、画面イベントの詳細な遷移・権限例外時の UI 仕様は確認できていません。
- フロントエンドの単体テストコードは未作成前提でレビューしており、将来のテスト実装方式（Jest/Vitest/RTL 等）は未確定です。
- サーバー側で最終的な認可をどこまで担保しているかは、本レビューではフロントエンド観点の確認に留めています。
